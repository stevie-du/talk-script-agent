## 二、句式类，我们的词表引擎形态收不了（需要新结构 tell，或明确不做）

- 不仅……也
- 看似 X，本质 Y
- 表面 X，背后 Y
- 既要 X 又要 Y
- 不是……而是……
- 与其……不如……
- 构成……而非……
- 从 X 到 Y 再到 Z
- 在……背景下
- 负面事实＋未来可期
- 这意味着→这说明→进一步→由此可见

→ qu-ai-wei 是 prompt 工程（整段判断），我们是词表 + 正则。这类要么新增
  结构 tell（如 `contrast_frame`「不是X而是Y」/`scale_jump`「从X到Y再到Z」），
  要么认盲区。**建议本轮认盲区**：它们跨句、形态开放，正则化的误伤面
  会比 list_enumeration 更大（那个 97% 命中的教训在前）。

## 三、有歧义，单收会误伤（qu-ai-wei 是与抽象名词搭配才判）

- 体现
- 参与
- 可能
- 基于
- 实现
- 推动
- 提醒
- 构建
- 相对
- 进行
- 通常
- 通过

→ 「体现 / 进行 / 实现 / 推动 / 构建 / 通过 / 基于」单独出现全是正常动词，
  qu-ai-wei 的判据是「体现＋抽象名词」这类**搭配**。我们引擎按 len>=2 单字
  匹配，收进去就是新一轮 169/175 式假命中。**不收**，与 A-6 #5 的留待校准同理。
