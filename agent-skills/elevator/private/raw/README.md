# 原始资料投放区

**把资料文件直接丢进这个目录就行。** 不用整理、不用转换格式、不用改文件名。

支持：PDF、Word、Excel、CSV、图片（截图/照片）、TXT、Markdown

---

## 工作流

```
① 把文件丢进本目录
        ↓
② 跟我说一句：「处理一下 raw 里的资料」
        ↓
③ 我读取全部文件，抽取成结构化条目，写进上层 products.yaml / service.yaml / cases.yaml / faq.yaml
        ↓
④ 你核对一遍（我会列出抽取结果）
        ↓
⑤ 完成。以后生成脚本自动使用，你不用再提
```

原始文件**保留在这里备查**，不删除。日后资料更新，替换文件再让我处理一次即可。

---

## 为什么要"抽取"这一步，不直接读原始文件

因为 Skill 每次生成脚本都要读知识库。

| 方式 | 每次消耗的上下文 |
|---|---|
| 直接读 100 页产品手册 | 数万 token，且大部分是无用排版 |
| 读抽取后的 yaml | 几百 token，全是有效字段 |

**原始文件 = 源码，yaml = 编译产物。** 编译一次，之后每次运行都轻量。

资料更新时重新"编译"一次就行。

## 命名建议（可选，方便日后管理）

```
raw/
├── 产品手册_2026版.pdf
├── 型号参数表.xlsx
├── 案例清单.xlsx
├── 服务承诺与报价规则.docx
└── 政策文件_加装电梯补助.pdf
```

按资料类型命名即可，不需要严格规范。

---

## 敏感信息处理

不需要的文件不要放进来。以下内容建议**不要**投放：

- 含客户联系方式的名单
- 含成本底价的报价表
- 竞品内部资料
- 未公开项目文件

**报价表的正确用法**：给我看可以，但我只会抽取**构成规则**（哪几部分、占比逻辑），不把具体底价写进知识库。

## 常见资料对应的目标文件

| 你丢进来的 | 我抽取到 |
|---|---|
| 产品手册、型号参数表 | `products.yaml` |
| 服务承诺、资质证书、响应时效 | `service.yaml` |
| 案例清单、完工照片、验收单 | `cases.yaml` |
| 客户异议记录、销售话术、客服记录 | `faq.yaml` |
| 政策文件、补贴办法 | 抽取要点写进 `faq.yaml` 政策类 |
