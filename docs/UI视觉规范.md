# TalkScript UI 视觉规范

> 目的：**统一**（同一种东西只有一种画法）与**极简**（一屏内可数的视觉手法）。
> 现状问题不在配色，在于「同一语义多套数值 + 多种层次表达混用」。
> 实测基线（设置页一屏 80 个可见元素）：4 档控件高度、3 档圆角、6 档字号、
> 7 档 gap、3 种阴影、4 种卡片底色并存。本规范把它们各自收敛成可数的几档。
>
> 适用范围：先试点 `设置页`，验收后再逐视图推。

## 一、两条总则

1. **一个元素只用一种手法表达「它在第几层」。** 描边、阴影、玻璃、底色是四种表达层次的手段，
   同一元素最多用其中一种。卡片不得同时吃 描边 + 阴影 + 渐变。
2. **数值只能来自下面的刻度表。** 表里没有的值不许新写；要加档先改本规范。

## 二、刻度表（收敛后）

| 维度 | 只允许这些值 | 被合并掉的 |
|---|---|---|
| 间距 | `--s1 4` `--s2 8` `--s3 12` `--s4 16` `--s6 24` `--s8 32` | `--s5 20`；以及实测的 2/3/5/6/9/11px |
| 圆角 | `--r-ctl 8`（控件/图标块/小卡）`--r-card 12`（卡片/容器）`--r-pop 16`（弹层）`--r-pill` | `--r-xs 6`、`--r-sm 8`（与 `--r-ctl` 同值双名）、`--r-ctl 9`、`--r-md 10`、`--r-lg 14`、`--r-xl 18` |
| 控件高度 | `--h-sm 28`（紧凑/图标钮）`--h-md 32`（常规）`--h-lg 40`（主 CTA） | `--h-btn 30`、`--h-icon 30`、`--h-btn-lg 32`（与 `--h-md` 同值双名）、实测的 34/36px |
| 字阶 | `--f-2xs 11`（字段标签/计数）`--f-sm 13`（控件、列表、提示文字）`--f-md 15`（正文与卡片标题，标题靠字重区分）`--f-xl 20`（页标题） | `--f-min 10`、`--f-xs 12`、`--f-base 14`、`--f-lg 16` |
| 字重 | `400` 正文 / `500` 控件与导航 / `600` 标题 | 不允许再出现第三第四种 |
| 动效 | `--dur .16s` 一个时长 + `--ease` 一条曲线 | 实测 6 档 .12/.14/.15/.16/.18/.22s |
| 描边 | **一律 `0.5px solid var(--line)` 发丝线**（HiDPI 下最精致的边界；不用 1px 重线） | `1px` 与 `0.5px` 两种线宽表达同一语义 |

**4 的倍数是硬约束**：间距、圆角、控件高度、图标盒一律取 4 的整数倍。
刻度表里所有值都满足；改前实测的 2/3/5/6/9/11px 与 30px 高的图标列全部违规，
分别并入 4 / 8 / 12 / 28。字号不受此约束（走字阶表）。

**三类例外，写明才允许存在**：
1. **光学微调 ≤ 2px** —— 药丸内边距、图标与文字的 1px 视差、上下不对称的 1px 补偿。
   这类值不是在定节奏，是在补偿字形度量；强行并进 4 的倍数会把对齐弄坏。
   必须带注释说明"补的是什么"，否则按违规处理。
   同一类里还有**状态圆点 4 / 6 两档**（`.dot::before`、`.step-dot`、警示小圆点）：
   圆点是字形尺度的记号，不是图标盒，套 4 的倍数只会把它推到看不见或推到太大。
2. **发丝线相关的 0.5px 偏移**（`top: 0.5px`、`box-shadow` 的 0.5px spread）——
   那是线宽本身，不是间距。
3. **涂底行之间的 1px 缝**（`#session-list`）—— 相邻两行都会涂底（选中 / 悬停），
   缝给 0 会连成一整块、"哪一条正开着"读不出来；给 4 又把密集列表松开。
   这是缝隙不是节奏，只允许出现在"两侧都有底色"的这一种地方。

**刻度表由 `_verify/verify.js` 静态扫 `styles.css` 校对**：表外的间距 / 圆角值有一份白名单，
新增一处必须先过那条断言（写不进名单就说明它没有补偿对象），修好一处不删条目同样会红。

## 二·五、精致化的六条细则

统一数值只是及格线，"精致"来自下面这些不显眼的一致性：

1. **图标只有一套笔画**：SVG 线宽一律 `1.6`，尺寸按第四节那四档取，颜色继承 `currentColor`。
   改前设置页里 `1.8 / 2 / 2.4` 三种线宽并存，图标看着"粗细不一"就是这个。
2. **字距一档**：标题 `letter-spacing: -.02em`（相对值，不写死 px），正文与控件 `0`。
   改前 `-.3px / -.2px / -.1px` 三份绝对值，字号不同却用同一个 px 值，等于没统一。
3. **行高两档**：控件与标签 `1.35`，正文与说明 `1.6`。不写第三种。
4. **hover 只用一种手法**：底色 `--fill`。不得 hover 时又加描边又加阴影又位移。
   （位移只允许出现在主 CTA 与卡片抬升，且幅度 ≤ 1px。）
5. **焦点环一个配方**：`--shadow-focus`，所有可交互元素共用；自绘控件必须让焦点环
   落在**看得见**的那个元素上（不能落在 `.native-hidden` 的 1px 透明原生 select 上）。
6. **同层级同呼吸**：同一列里所有条目的高度、内边距、图标盒必须逐项相等；
   并排的两个控件不得出现 1px 的底边差。

## 三、层次（elevation）只有三档

层次用**发丝线 + 低阴影**表达：边界一律靠 0.5px 发丝线立住，阴影只做"离开纸面一点点"，
透明度压在 .10 以下。不允许用重阴影表达层级。

| 档 | 用于 | 取值 | 取代 |
|---|---|---|---|
| `--e1` | 表单控件、列表项的边（发丝描边，不占布局） | `0 0 0 0.5px var(--line)` | `--shadow-input` / `-input-hover` / `-ghost` / `-selected` |
| `--e2` | 页面内卡片（发丝边 + 极轻抬起） | `0 0 0 0.5px var(--line), 0 1px 2px rgba(0,0,0,.04)` | `--shadow-raised` / `-lift` / `-composer` |
| `--e3` | 浮层：菜单、弹窗、toast | `0 0 0 0.5px var(--line-strong), 0 8px 24px rgba(0,0,0,.10)` | `--shadow-pop` / `-ink-lg` |

- 状态环（`--shadow-focus`、`--shadow-flash`）是**状态**不是**层次**，单独保留，不得拿来表达层级。
- **弹层里装着「一行」时，容器圆角取同心值 = 行圆角 + 容器内边距**（现 8 + 4 = 12，即 `--r-card`），
  不用 `--r-pop` 的 16。外圈比内圈更圆，四角就"包不住"里面的行；只有一项的菜单更会被
  整个画成一颗胶囊，读成"一个按钮后面垫了张卡"。没有行的弹层（模态框）仍走 16。
  判据由 `_verify/verify.js` 现算比对，不写死数字。
- 深色主按钮的 `--grad-btn` / `--shadow-ink` 属「实心控件」一族，只允许出现在主 CTA，不得扩散到卡片。
- **玻璃（`backdrop-filter`）只允许用于「浮在滚动内容之上」的固定层**（侧栏、顶栏、弹层）。
  卡片、表单、列表项一律不得用玻璃底。
- 卡片底色只有两级：`--surface`（白）与 `--fill`（4%）。`--fill-strong`、5%、7% 的散写值收掉。

## 四、图标只允许一种语言

- 内联 SVG，`stroke: currentColor`，**线宽一律 1.6**（CSS 里一条 `svg{stroke-width:1.6}` 收口，
  因为 `stroke-width` 是 presentation attribute，CSS 声明能盖住 HTML 上写死的 1.5/1.8/2/2.4）。
- 尺寸只有三档 + 一个展示档：**14**（行内符号、箭头、勾选）/ **16**（控件与列表）/
  **18**（导航与区块标题）/ **32**（空态 hero）。
  实测改前有 8 种尺寸（11/12/13/14/15/16/17/18）并存 —— 同一屏里两种图标差 1px
  看不出"不统一"，但差 3px 就明显是两套东西。
- **禁止**用文本字形当图标：`⚠  ✅ ❌  ✕ ⌄ ▸ ▾ ▴ ℹ `。正文里作箭头/连接符的 `→` 不在此列。
- 已知的双图标缺陷即此条的产物：`.banner::before{content:"⚠"}` 与 JS 文案自带的 ⚠/ 叠加，
  最醒目的横幅会显示成「⚠ 」。修法：**CSS 不再注入图标，图标只由 JS 出一次**。

## 五、文字对比度：第三档灰已并入第二档

- 正文级（≥11px 且承载信息）文字对比度 **≥ 4.5:1**；纯装饰可低于此。
- 原 `--text-3 #a1a1a6` 白底实算 **2.57:1**，不达标，而它有 44 处用法几乎都在承载信息
  （副标题、meta、占位说明、计数、导航图标）。
- **数学上没有第三个位置**：达标下限约 `#707075`，与 `--text-2 #6e6e73` 只差 2~3 个色阶，
  并排看不出区别 —— 那就不是一档，是噪声。所以 `--text-3` 现在只是 `--text-2` 的别名，
  保留名字以免改 44 处引用；**不要再新增使用点**。
- 需要"更弱"的表达请用**非文字色**：`--line` / `--line-strong` / `--fill-*`。
  把文字色当装饰色，是这档灰当初被写出来的真正原因，也是它不达标的真正原因。
- 例外：禁用态控件文字允许低于 4.5:1（WCAG 明确豁免），但它靠"不可点"表达，不靠变灰。

## 六、试点验收（设置页）

改完必须同时满足，否则不算过：

1. `node _verify/verify.js` 全绿（断言条数跑一下就出来，**不抄进本文档** —— 抄了必然过期），
   **不许改断言迁就实现**；判据确实要换的，写成"量哪个维度"而不是"放宽到多少"。
2. 一屏内实测：控件高度 ≤ 2 档、圆角 ≤ 2 档、阴影 ≤ 2 档、`gap` 全部来自刻度表、
   卡片底色 ≤ 2 种。用 `getComputedStyle` 遍历可见元素统计，不靠目测。
3. 键盘 Tab 走一遍：焦点可见、每个下拉只有 1 个停靠点。
4. 改前/改后截图留档（`_verify/_ui-*.png`，下划线开头即临时件，不入库）。

## 七、本轮明确不做

- 不改配色族、不做暗色主题、不动布局骨架（三列结构本身等试点看完效果再议）。
- 不批量重命名既有 class。
