# 场景序列（Scene[]）契约

> 核心思想：一切输出视图都是「场景序列」的投影。
> 口播 = 旁白文本投影 · 分镜 = 表格投影 · 视频时间轴 = 连续投影 · 剪辑台 = 编辑投影

## 一、统一产物模型

当前 `ScriptSection[]` + `StoryboardShot[]` + `timings[]` 是三个平行数组，中间靠索引隐式关联，脆弱且对渲染端不友好。**场景序列**将它们合并为一个自包含的数组：

```json
{
  "scenes": [
    {
      "scene_id": "s1",
      "type": "hook",
      "start": 0.0,
      "end": 8.5,
      "narration": "你家的电梯是不是也经常这样？",
      "subtitle": "电梯经常这样？",
      "visual": {
        "prompt": "老旧小区楼道，居民爬楼梯气喘吁吁",
        "source": "generated",
        "transition": "cut"
      },
      "audio": {
        "bgm": "ambient-1",
        "sfx": "footstep"
      },
      "shot_type": "medium",
      "style": "纪实"
    }
  ]
}
```

> 命名约定：全部字段沿用引擎既有输出的 **snake_case**（与 `sections` / `timings` 一致），渲染端在适配层做驼峰映射。

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scene_id` | string | ✓ | 场景唯一标识，如 `s1` `s2` |
| `type` | enum | ✓ | `hook` / `point` / `cta` —— 继承文案结构语义 |
| `start` | float | ✓ | 本镜起始时间（秒），由语速+字数计算 |
| `end` | float | ✓ | 本镜结束时间（秒） |
| `narration` | string | ✓ | 口播旁白全文，渲染端据此生成 TTS / 配音 |
| `subtitle` | string | | 字幕关键词（≤12 字），为空时由 narration 截取 |
| `visual.prompt` | string | | 画面描述 → 素材生成提示词或素材库检索 key |
| `visual.source` | enum | | `generated` / `stock` / `user` —— 素材来源 |
| `visual.transition` | enum | | `cut` / `dissolve` / `fade` —— 转场方式 |
| `audio.bgm` | string | | BGM 标识，空=沿用上一镜 |
| `audio.sfx` | string | | 音效标识，空=无 |
| `shot_type` | enum | | `closeup` / `medium` / `wide` / `detail` |
| `style` | string | | 与本镜匹配的视觉风格标签 |

## 二、映射规则（当前 → 新契约）

```
sections[i]  +  timings[i]  +  storyboard[i]
            ↓
       scenes[i]
```

- `sections[i].text` → `scenes[i].narration`
- `sections[i].subtitle` → `scenes[i].subtitle`
- `sections[i].type` → `scenes[i].type`
- `timings[i].start / .end` → `scenes[i].start / .end`
- `storyboard[i].shot` → `scenes[i].visual.prompt`
- `storyboard[i].sfx` → `scenes[i].audio.sfx`
- `storyboard[i].note` → 暂存，可映射到 `scenes[i].visual.prompt` 补充或丢弃
- `storyboard[i].voiceover` → 与 `narration` 合并；若不同则保留为 `scenes[i].voiceover_direct`（v1 暂不输出）

**兼容阶段**：`ScriptResult` 并行保留 `sections` + `storyboard` + `timings` 旧字段，同时新增 `scenes` 字段。前端和渲染端按需两端读取，逐步迁移。

## 三、渲染端消费方式

### Remotion 程序化渲染

```tsx
// scenes → React <Sequence> 映射（适配层将 snake_case 映射为 camelCase 后消费）
const SceneComposition = ({ scenes }) => scenes.map(scene => (
  <Sequence
    key={scene.sceneId}
    from={Math.round(scene.start * fps)}
    durationInFrames={Math.round((scene.end - scene.start) * fps)}
  >
    <SceneFrame
      narration={scene.narration}        // → TTS + 字幕轨道
      visualPrompt={scene.visual.prompt} // → 图片/视频素材
      transition={scene.visual.transition}
      bgm={scene.audio.bgm}
      sfx={scene.audio.sfx}
    />
  </Sequence>
));
```

### AI 生成式视频

逐镜将 `visual.prompt` 作为视频生成 API 的 prompt body，`narration` 作为配音文本，每镜并行生成，按 `start/end` 切片拼接。

### 剪辑时间轴

场景卡片列表 = 时间轴轨道的可视化：拖拽排序 = 重排 `scenes[]` 数组，增减/替换素材 = 修改 `visual.source` 和 `prompt`。

## 四、前端消费方式

### 口播视图（当前）

```
scenes.map(s => ({ type: s.type, text: s.narration, subtitle: s.subtitle }))
```
→ 与当前 `sections[]` 等价的卡片列表。

### 分镜视图（当前）

```
scenes.map(s => ({
  time: `${s.start}-${s.end}s`,
  shot: s.visual.prompt,
  subtitle: s.subtitle,
  sfx: s.audio.sfx
}))
```
→ 与当前 `storyboard[]` 等价的表格。

### 对话流消息渲染

生成结果消息体 = `scenes[]`，渲染时展开：
- 折叠态：标题 + 指标（总时长 / 镜数 / 字数）
- 展开态：场景列表，与当前口播卡片一致

## 五、实现路径

### 阶段一（本次）

1. 在 `schemas.py` 中新增 `SceneItem` 模型
2. 在 `ScriptResult` 中新增 `scenes: list[SceneItem]` 字段（可选）
3. `Pipeline._finalize()` 中组装 `scenes` 数组，与 `sections` / `storyboard` / `timings` 并行输出
4. 前端兼顾新旧字段

### 阶段二（UI 对话流改造）

1. 前端完全切换到 `scenes` 字段
2. 移除 `sections` / `storyboard` / `timings` 旧字段
3. 对话流 + 底部输入栏 + 左栏会话记录

### 阶段三（渲染管线）

1. Remotion 或 AI 视频渲染端接入 `scenes` 契约
2. 前端增加「制作视频」入口
3. 时间轴编辑视图

## 六、不变原则

- **场景序列是只读的一次性产出**，渲染端可读但不可写。用户编辑场景 → 新建一条 `rewrite` 记录，不原地修改
- **场景序列不包含资源文件本身**，只包含 `prompt` 和 `source` 标识。资源解析 / 素材检索是渲染端职责
- **场景序列应当可增量同步**，适合流式输出（每生成一个场景就推送一个）。渲染端也可按镜并行消费
