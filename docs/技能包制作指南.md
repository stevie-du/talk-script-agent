# 技能包制作指南（第三方作者）

> 2026-09-23。给想给 TalkScript 写行业包的人。导入/平台侧的设计见
> `docs/技能包系统方案.md`——那份是内部方案，这份是**你的**手册。
>
> 一句话版本：一个技能包 = 一个含 `pack.yaml` 的目录。写完之后跑
> `python -m app.packcheck <你的目录>` 自检，通过就能打包分享。

## 1. 包长什么样

```
my-pack/
├── pack.yaml        # 必需：清单（这个包是什么、有哪些参数）
├── skill.yaml       # 必需：提示词模板（撰写/回炉怎么调模型）
├── banwords.yaml    # 必需：合规词表（硬禁用/软禁用）
├── ai_tells.yaml    # 可选：人味 tell 声明（不写 = 这个包不跑人味检测）
├── patterns/        # 可选：注入模型的清单（*.md，如 anti-ai-smell.md）
├── knowledge/       # 可选：知识文件（voice.md、standards.md…）
├── compliance/      # 可选：合规文件（**红线速查在 compliance/industry.md**）
├── rules/           # 可选：其它规则文件
└── private/         # 可选：私有资料 —— **分享前删掉它**（见 §6）
```

引擎只认**白名单内的文件类型**：`.md` `.yaml` `.yml` `.txt` `.json`。
**不能有 `.py` / `.exe` / 任何可执行文件**——包是数据不是代码，这是硬规则。

## 2. pack.yaml 最小可用示例

```yaml
name: my-pack                 # 必需：包的身份（目录名即身份，同名=替换）
display_name: 我的行业包       # 界面显示名
version: 1                    # 必需：≥1 的整数。改内容就 +1
description: 一句话说明这个包是干什么的
pack_api: 1                   # 可选：技能包格式版本。省略=1。将来的引擎
                              # 不兼容时会拒绝并提示升级，而不是静默降级
source:                       # 可选：来源声明（导入方看得到）
  author: 你的名字
  homepage: https://…   # ⚠ 引擎目前只读 author / license（packimport.py），homepage 不进界面
  license: MIT                # ⚠ 强烈建议写 —— 导入方有权知道自己装了什么

banwords: banwords.yaml       # 可选：合规词表文件路径（默认 banwords.yaml）

params:                       # 可选：界面参数条。每个参数 = 一组选项
  segment:
    label: 细分领域
    options: [整机改造, 维保, 旧楼加装]
    default: 维保
  audience:
    label: 受众
    options: [业主乘客, 物业业委会]
    default: 业主乘客
  duration:
    label: 时长（秒）
    options: [15, 30, 60]
    default: 30
```

### params 的规则（来自真实引擎行为）

- 每个参数**必须**有 `label`（界面显示）、`options`（可选值）、`default`（默认值）
- `default` 必须在 `options` 里 —— 不在的话该参数条会标「本包没定制」的审计提示
- 参数值会以 `$参数名` 注入提示词模板（如 `$segment`、`$audience`）
- 用户能选但包里没写对应定制内容的值，引擎会在界面上**明说**（不静默走默认）

## 3. skill.yaml 最小可用示例

```yaml
stages:
  write:
    # 撰写轮的用户提示词。可用占位符：
    #   $topic $segment $audience $duration $style $persona $cta $platform
    #   $anti_ai_rule（人味规则，按档位注入）$voice_block $plan_json
    #   $facts_block $intel_block $alt_guide $feedback_block
    user_template: |
      请为「$segment」领域的「$audience」写一段 $duration 秒口播稿。
      主题：$topic

      $anti_ai_rule
      $facts_block

      输出 JSON：{"sections": [{"type": "hook|point|cta", "text": "…"}]}
```

**必须知道的三件事**：

1. `$feedback_block` 在模板里的位置由引擎固定放在**末尾**（前缀缓存要求），
   你写在别处不会生效
2. 回炉轮与首轮走**同一份** `stages.write` 模板 —— 改一处两边都变
3. `$anti_ai_rule` / `$voice_block` 由人味档位（strong/standard/off）组装，
   你在 `anti_ai.levels` 里声明每档注入哪些文件（见 elevator 包的 skill.yaml）

## 4. banwords.yaml 最小可用示例

```yaml
hard: []          # 硬禁用词：命中即不合格（合规红线，必须改）
soft: []          # 软禁用词：命中不阻塞，但反馈里提醒改
```

**引用它的文件必须真实存在**——`banwords: xxx.yaml` 指向一个不存在的文件，
导入会被拒（那不是"少个文件"的小事：合规校验会静默全过，是最危险的失效）。

## 5. 自检与打包

```bash
# 自检（强烈建议每次打包前跑）——判定与 TalkScript 导入完全一致
python -m app.packcheck my-pack/

# 通过后打包：zip 根直接是包目录，或裹一层同名目录，两种都认
cd my-pack && zip -r ../my-pack.zip .        # 或资源管理器"发送到压缩文件"
```

CLI 输出三种信息：✓ 通过（包名/版本/作者/许可证/文件数）、✗ 人话原因、
⚠ 提醒（含 `private/` 没删 / 没写许可证）。**退出码**：0 通过 / 1 拒 ——
可以写进你的打包脚本里当门禁。

## 6. private/ 约定（分享前必读）

`private/` 放你的商业资料（产品价目、客户名单、内部口径）。引擎**永不**
把它带进播种、界面也读不了它的全文。**分享/导出包时删掉它**——
带着它分享 = 把你的商业信息一起给出去了。CLI 检测到会提醒你。

## 7. 常见坏法（导入被拒的真实原因）

| 你写了 | 会被拒的原因 |
|---|---|
| `name: ../../evil` | 包名只能字母/数字/中文/连字符，不许有路径字符 |
| `version: "v2"` | version 必须是**整数**（`v2` 是字符串，`int()` 会炸） |
| `pack_api: 99` | 超过了当前引擎认识的格式版本（等升级，别手工改） |
| `banwords: ../../x.yaml` | 引用路径跑到了包外面 |
| 引用了 `notes.md` 但没打进 zip | 引擎加载时要读的文件必须真实存在 |
| 包里放了 `setup.py` | 只接受 `.md/.yaml/.yml/.txt/.json`，可执行文件一律禁 |
| 导入时提示"你改过内置包" | 目标机器上有个同名**且被改过**的内置包，导入会丢用户的修改，所以拒 —— 让用户先备份或改名 |

## 8. 测试你的包（发布前最后一步）

自检只证明"结构合法"，不证明"能生成出东西"。真正的验收：

1. 把 zip 导入 TalkScript（设置 → 行业包 → 导入）
2. 选它、走一遍完整生成（含一次回炉）
3. 看产物：参数条正常吗？提示词占位符都落值了吗？人味分（若配了
   `ai_tells.yaml`）在动吗？

**别人拿你的包跑不出稿子，比结构错更难堪**——结构有 CLI 拦，内容没有。

## 9. 参考实现

`packs/elevator/`（本仓库内置）是完整的真实样例：三档人味、tell 词表、
情报源声明、私有资料、知识文件全都有。照着改比从零写快。

## 10. `ai_tells.yaml`：加词与维护纪律（A-9）

人味检测管**像不像人说话**，不管合不合规（那是 `banwords.yaml`）。命中不进 `passed`，
但会进分数、进 `脚本.md`、进回炉点名 —— 所以词表是一把有后果的尺子。

### 10.1 条目写法（三种形态引擎都认）

```yaml
lexicon:
  abstract_noun_ending:
    - 赋能                                    # ① 纯词
    - 闭环: 仅黑话义                           # ② 词 + 给人读的限定说明
    - 抓手:                                    # ③ 词 + 说明 + 机器可判的豁免
        note: 仅黑话义（"作为抓手"式收尾）
        unless: [防滑抓手, 轿厢扶手]
  opening_ban:
    - "re:在当今[\\s\\S]{0,12}(?:时代|社会|背景下)"   # 正则条目：**只有开场禁区认**
thresholds:            # 可选：只有 weak 的词表类与 contrast_frame 吃这个覆盖
  cliche_hook: 3
idioms:                # L2「成语密度」的表（只在包里，代码里零具体词）
  - 至关重要
```

- **`unless` 是"报得准"的那一半**：命中处撞上这些短语就放过。行业真术语撞上市面
  通用黑话表时（电梯的「维保工单闭环」对 AI 黑话的「闭环」），**不要删词**，加豁免。
  ⚠ 豁免短语必须 ≥2 字：单字（如 `环`）与任何命中都重叠，等于把整条 tell 静默打死 ——
  这种条目引擎会报进 `config_warnings` 并丢掉。
- **同一个词不要写两条**：YAML 里后者会覆盖前者（`{闭环: 说明}` 写两遍只剩最后一条），
  所以三种形态是**同一词的三种写法**，不是一条词表里并列三份。
- **`note` 跟着命中进回炉反馈**，免得模型/人把真术语当黑话改掉。
- **提示词与词表要对齐**：voice.md 的"多用词"鼓励「其实呢」，而 `filler_stack` 收着「其实」——
  给「其实」加 `unless: [其实呢]`，否则提示词叫你用、引擎扣你分（两个包都同步改了）。
- **`re:` 只用在 `opening_ban`**（它的判据是"首句以…开头"，需要框架而不是词）。
  用在别的类会被引擎报进 `config_warnings` 并**跳过** —— 因为字面量扫描会把正则当一串
  普通字符，得到一条"看着配了词、永远不命中"的死词。
- **`thresholds` 只对两类有效**：weak 的词表类与 `contrast_frame`。写给 strong
  （单次即报）或别的结构类（各有自己的判据）是 **no-op**，引擎会报"不生效"并忽略 ——
  不会反过来谎称你换了口径。真正生效的非默认值必进 `config_warnings`，且必须是整数。
- **`idioms` 不得与 tell 词表重叠**，且两个包的这份表要一致（同一次命中不该既报 tell
  又算成语密度；`_template` 是新包的出生起点，不一致就是两份口径）。

### 10.2 三条硬约束（写错不会报错，只会静默失效）

1. **词 ≥2 字**：引擎按 `len(w) >= 2` 过滤，单字（裸「性」「度」「化」）写了等于没写；
2. **同类里互不为子串**：扫描是"长词优先、不重叠"，同时收「普遍认为」与
   「专家普遍认为」会让短的那个永远取不到，而且计数虚高；
3. **tell 名必须是引擎认识的那 14 个**，且**每个包声明的集合要与需求方案 §2.1 完全相等**
   （`tests/test_aitells_alignment.py` 三方对账）。少声明一个 = 这个包不跑它，
   多声明一个 = 拼错名字 —— 两种都判红。

### 10.3 加词/改阈值的合入纪律（A-9，本土化自 voice-guard 的回测纪律）

任何词表改动，**合入前必须跑两道闸**，两道都过才谈提交：

```bash
PYTHONUTF8=1 .venv/Scripts/python.exe -m pytest tests/test_aitells_false_positive.py
PYTHONUTF8=1 .venv/Scripts/python.exe _verify/ai-smell-distribution.py -v
```

（第二道要带 `-v`：默认只出分布汇总，看不到**是哪几条 tell 在历史稿上打到了**；
`-v` 才打每篇的命中明细。）

- 第一道是 **A-3 误报回归**：23 篇"人味本来就正常"的稿子，误报率必须 <10%
  且 **strong 命中为 0**；另外 5 类负样本（政策原文/法条/数字密集/引文/通报）
  **一条都不许中** —— 它们是被照抄进来的，任何"这里像 AI"的提示都会诱导人改坏文号与数字。
- 第二道是 **产物分布复跑**：拿 `generated/` 的真实产物重跑当前引擎，看新词在
  自己的历史稿上打了多少、分数分布有没有整体下移。

**误报超线的条目整条撤下，不是把阈值调高。** 调阈值等于把尺子换成一把更钝的，
而报告里看不出区别 —— 这正是 banwords soft 当年 169/175 轮假命中的复现路径。
（voice-guard 原文那条纪律更狠：12 篇自己满意的旧文回测，招牌装置被误报 >25%
 就把**整个机械判断层**丢掉只留规则层。我们本土化成"按条目撤"。）

### 10.4 tell 规格要"模式 + 量化门槛 + 豁免"三件套

一条 tell 只写"见到 X 就报"是不够的，规格（需求方案 §2.1 表）里要同时说清：
**什么样的形态算命中**、**同一段里几处才算**、**什么情况下必须放过**。
缺第三件的判据一定会误伤 —— 例：`unattributed`（「数据显示」）必须配"命中后 20 字内
出现具体数字/文号就放过"，否则「市场监管总局数据显示，2025 年…」这种有出处的真归因也被报。
