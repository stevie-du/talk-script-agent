# 知识库与技能配置指南

> 准备知识库内容（不管交给谁处理）所需的**内容格式规范与 AI 整理指令**，
> 见 **[知识库内容规范.md](知识库内容规范.md)**（含可直接复制给任何 AI 的提示词模板）。

TalkScript 是**通用**的口播脚本生成器：引擎不认识任何行业，每个行业是一个**行业包**（`packs/<行业>/`）。
一个包 = 四样东西：

| 组成 | 位置 | 回答的问题 |
|---|---|---|
| **知识库** | `knowledge/` | 写什么（行业知识点、受众痛点、选题） |
| **技能** | `skill.yaml` | 怎么写（各阶段提示词、注入哪些文件、回炉几次） |
| **合规词表** | `banwords.yaml` + `compliance/` | 什么不能写 |
| **私有资料** | `private/` | 你独有的事实（型号、报价逻辑、案例） |

**分享一个行业给同事 = 复制这个目录**（不含 `private/` 即不带商业信息）。

## 一、知识库怎么配置

### 目录结构与分工

```
packs/<行业>/
├── pack.yaml            # 清单：参数选项/默认值、语速、字数配额、章节映射、私有资料路径
├── skill.yaml           # 技能（见第二节）：**哪个阶段注入哪些文件写在这里，不写在 pack.yaml**
├── banwords.yaml        # 禁用词：hard（必改）/ soft（提示）× 平台 extra_hard / demote / promote
├── knowledge/
│   ├── topics.md        # 按细分领域分章（## N. 章节名），每章：核心知识点/常见误区表/需占位事实
│   ├── audience.md      # 按受众分章，每章：深层恐惧/高频疑问/推荐CTA
│   ├── ideas.md         # 选题库（编号列表；当前**不注入**，人挑选题用）
│   ├── standards.md     # 标准/法规索引（只写已核实的编号！；`## 核心术语` 一节可被注入）
│   └── voice.md         # 口语化与人设声音（人味档位注入）
├── patterns/
│   ├── hooks.md         # 钩子库（10 类）与风格模板 —— 选题阶段按风格切片注入
│   ├── growth.md        # 完播率/转化率要点 —— 撰写阶段注入
│   └── anti-ai-smell.md # AI 味自查清单 —— 人味档位注入
├── rules/               # 时长配额与输出模板（两份都是人读约定，不注入模型）
├── compliance/          # 广告法/平台规则/行业红线（只有 industry.md 经 write.files.redlines 注入）
└── private/             # 私有资料（见第四节）
```

### 两套"切片"机制，别混

| 机制 | 由谁决定 | 找不到时 |
|---|---|---|
| **哪些文件进哪个阶段** | `skill.yaml` 的 `stages.<阶段>.files`（**`pack.yaml` 里的 `files.select/write/...` 引擎不读**，只有 `files.private` 是活的） | 文件不存在 → 该占位符为空 |
| **一份文件里取哪一章** | 参数值 → `pack.yaml` 的 `topics_map` / `audience_map` → 章节标题关键词 | 见下面两行的区别 |

降级方向两份文件**不一样**（`app/knowledge.py:415-427`），照下表写才不会踩坑：

| 情况 | `topics_map`（细分领域） | `audience_map`（受众） |
|---|---|---|
| 参数值不在映射里 | 退到映射里名为「通用」的那一章 | **返回空串**（不注入整份） |
| 连「通用」都没有 / 映射值为空 | 返回**整份文件** | — |
| 映射到了，但那个章节名在文件里找不到 | 返回**整份文件** | 返回**整份文件** |

所以：**章节名写错 = 静默灌整份**，整份里别的章节会把模型注意力带走；
这一类降级由 `param_audit` 报出（第四节），不会在生成时报错。
匹配是**子串**匹配：`## 2. 旧楼加装` 用关键词 `旧楼加装`、`加装` 都能命中，
不必与标题逐字相同（电梯包就有意利用这一点：`行业观察` → `## 行业趋势`）。

### 映射怎么写

知识文件**不会全量**塞给模型，靠下面这两张映射表切到章：

```yaml
topics_map:            # 参数值 → topics.md 的章节标题关键词
  旧楼加装: 旧楼加装
  维保: 维保
audience_map:          # 参数值 → audience.md 的章节标题关键词
  业主乘客: 业主乘客
```

用户选了「旧楼加装」→ 引擎只取 `topics.md` 里含"旧楼加装"的那个 `##` 章。
**新建包时保证每个参数选项都在映射表里、关键词能命中一个真实章节** ——
上面那张降级表里的三种"退整份/退空"都是静默的，只在设置页的包体检里能看到。

### 格式规范（每个文件谁在读、要求什么）

**严格格式（引擎结构化解析，写错即失效）：**

| 文件 | 格式要求 |
|---|---|
| `pack.yaml` | 引擎真读的字段：`name`（包目录名，也是 `pack=` 的取值）、`display_name`、`draft`、`description`、`params.<名>.{options,default,label}`、`topics_map`、`audience_map`、`rate_by_style`、`quota_table`（每项固定 `total/hook/body/cta` 四键）、`points_by_duration`、`banwords`（词表文件名）、`files.private`。**除此之外不要加键**：`version` 目前是纯声明（解析但不消费），`files.select/write/compliance/facts` 这类"看着像配置"的死键已于 2026-09-20 删除 |
| `skill.yaml` | `$占位符` 语法见文件头注释；`stages` 四段：`select` / `write` / `storyboard` / `rewrite_segment`（缺 `storyboard` 的包会被跳过并留痕，不报错）；`anti_ai.levels` 固定 strong/standard/off 三档；`limits.recheck_rounds` = 校验不过时的回炉次数 |
| `banwords.yaml` | `hard:` / `soft:` 为字符串列表；`platform.<平台>` 下**只认** `extra_hard` / `promote` / `demote` 三种键 —— 写 `extra_soft` 不报错也不生效。**不要写单字条目**（见下） |
| `private/*.yaml` | 合法 YAML，字段名按模板；**只有"字符串叶子值里含 `示例：`"才被视为未填并剥离** —— 整条目级的示例（如一条只有 `type: 加装` 的空壳案例）剔不掉，会照原样注入，所以未填的条目请**整条删掉**而不是留着写"示例："；留空字段自动走占位符 |

> **⚠️ `stages.<阶段>.files` 的 key 必须与模板里的占位符同名。**
> 例：`write.files: {growth: patterns/growth.md}` 对应模板里写 `$growth`；
> 写成 `$growth_block` 不会报错（`Template.safe_substitute` 对未知变量保持原样），
> 但**文件不会被注入**，模型还会收到一段字面量 `$growth_block`。
> 引擎现在会检测未填充的占位符并记进作业「日志」页签，改完包记得看一眼。

> **⚠️ 禁用词表不要写单字条目**（如 `最`）：它会命中「最近」「最后」「最好」这类
> 正常用词，噪声远大于收益。要拦绝对化表述请写具体短语（`最低价` / `最便宜`）。
> 引擎会忽略单字条目，并在生成结果的合规区说明忽略了哪些。
> 另外命中判定是**不重叠**的：`包过检` 只算 1 处（归属给最长的词）。

**知识正文（模型上下文，格式自由但强烈推荐以下结构）：**

`topics.md` 每章三件套——核心知识点（带数字）、误区表、需占位事实：

```markdown
## 2. 旧楼加装

### 核心知识点
- 底坑深度与顶层高度是能否加装的两大硬条件
- 管线迁改常是预算超支主因

### 常见误区
| 误区 | 事实 |
|---|---|
| 一楼一定反对 | 关键在补偿方案与沟通 |

### 需占位的事实
本地造价区间、补贴标准 → {{待补}}
```

`audience.md` 每章：深层恐惧（顿号短语）/ 高频疑问（列表）/ 推荐 CTA。
钩子库 `patterns/hooks.md` 必须含类型表（选题阶段要求 hook_type 从中选），
并且按 `## 一、钩子库…` + `### <风格名>`（风格名与 `pack.yaml` 的 style 选项一致）
两级的结构写 —— 引擎按风格只注入当前那一套（`Pack.hooks_slice`）。

**消费关系（诚实说明，避免无效劳动）：**
- 引擎**生成时真读**的：`topics.md`/`audience.md` 对应章节、`hooks.md`、`growth.md`、
  `voice.md`、`anti-ai-smell.md`、`compliance/industry.md`（行业红线，注入 write 阶段）、
  `private/*.yaml`、`banwords.yaml`、`pack.yaml`、`skill.yaml`
  —— 注入清单以 `skill.yaml` 的 `stages.<阶段>.files` 为准：**没写进去的文件引擎不看**
- **人 / agent 参考**用、生成时不注入的：`ideas.md`（人挑选题用）、`standards.md`
  的法规编号部分（人工核对；只有 `## 核心术语` 一节按 `write.files.terms` 注入）、
  `compliance/ad-law.md`/`platform.md`（细则，硬约束由 banwords 校验执行）、
  `rules/duration.md`（时长与语速的推导过程；实际取值走 `pack.yaml` 的
  `rate_by_style`/`quota_table`/`points_by_duration`）、
  `rules/output-template.md`（给人看的排版样式；模型输出的结构契约在 skill.yaml）
- 这些文件对**导出的 Agent 技能**依然重要（agent 会按 SKILL.md 自行读取）
- ⚠ **目前没有任何测试会替你发现孤儿文件**：新写一份 md 而忘了在 `skill.yaml` 里挂上，
  它会永远进不了提示词且无人报警（电梯包现在就有 5 份这样的文件：
  `ad-law.md`、`platform.md`、`ideas.md`、`rules/duration.md`、`rules/output-template.md`，
  都是有意的人读物）。离线验一眼渲染结果（不发请求、不落盘）：

  ```bash
  .venv/Scripts/python.exe -c "import sys;sys.path.insert(0,'.')
  from pathlib import Path;from app.knowledge import Pack;from app.prompts import PromptRenderer
  pk=Pack(Path('.').resolve(),'elevator');pr=PromptRenderer(pk)
  # 用 app/pipeline.py 里同款的 ctx 构造参数，或直接打印 pr.file_text / Pack.file_slice 的返回值
  print(len(pk.file_slice('compliance/industry.md')), len(pk.file_slice('knowledge/standards.md#核心术语')))"
  ```

  返回 0 就说明这条 `files` 声明其实注入不到东西（章节名对不上是**静默**的，
  只有 `tests/test_prompt_templates.py` 的那条对账测试会报红）。
  另一个信号是作业日志里出现 `tpl_<阶段>`「模板占位符未填充」 —— 它说明
  `files` 的 key 与模板里的 `$占位符` 名字不一致，知识同样没进去。

### 新增一个细分领域的步骤

1. `pack.yaml` → `params.segment.options` 加一项（如 `板材环保`）
2. `topics_map` 加映射 `板材环保: 板材环保`
3. `knowledge/topics.md` 加 `## N. 板材环保` 章节（核心知识点 + 误区表 + 需占位事实）
4. `knowledge/ideas.md` 补几条该细分的选题

## 二、技能（skill.yaml）怎么配置

技能 = **生成方法**。改它就能让同一份知识库写出不同风格的稿子。

```yaml
limits:
  recheck_rounds: 2        # 校验不合格自动回炉次数
stages:
  select:                  # 选题阶段：system + user_template + 注入文件
  write:                   # 撰写阶段：含 anti_ai（人味三档的规则与注入文件）；只出 sections
  storyboard:              # 分镜阶段：正文校验通过后单独跑一次（format=voice 时整个跳过）
  rewrite_segment:         # 单段重写阶段
```

阶段顺序固定为 select → (write ⇄ check) → storyboard → done。分镜单独成阶段是为了
省钱与省时：画面描述的字数与口播同量级，并给 write 会让**那一次调用**的输出与思考量成倍上涨
（电梯包实测 110~127s → 12~23s，注意那是单次撰写调用的数字，端到端还要加回分镜这一次调用），
更关键的是**回炉的每一轮不再连带重画分镜**。缺 `storyboard` 阶段的旧包会被**跳过并留痕**
（日志 `storyboard_skip`），不会让已经写完的正文以失败收场。

两条要知道的不对称（都是当前实现的真实行为）：
- **生成路径**上分镜调用失败 = 整条作业判 `failed`，哪怕正文刚通过校验；
  **单段重写**路径相反 —— 重画失败只留痕、沿用旧分镜（`app/pipeline.py:316-332` vs `:698-712`）。
- 模型返回的 `time` **不校验也不覆写**：时间轴虽由引擎算好后写进提示词，但产物里仍以模型给的
  `time` 为准、算出的 `timings` 兜底，段数不符只记一条 `storyboard_mismatch`。

**常见改法**：

| 想要 | 改哪里 |
|---|---|
| 语气更收敛 | write.system 里的口语化规则，收紧第 7 条 |
| 更强反 AI 味 | anti_ai.rule 加严 + levels.strong.files 增加范文文件 |
| 不同行业不同写法 | 每个包一份 skill.yaml，互不影响 |
| 回炉更严格 | limits.recheck_rounds 调大（每多一次多一次模型调用） |
| 换注入的知识文件 | stages.write.anti_ai.levels.*.files 增删路径（不存在的文件自动跳过） |

**各阶段的输出预算不在 skill.yaml 里**，写死在引擎：选题 4000、分镜 4000、单段重写 3000，
只有撰写用配置里的 `llm.max_tokens`（`app/pipeline.py`，包作者改不了）。
包能影响的是**配额与容差**：字数配额查 `quota_table`、要点数查 `points_by_duration`、
语速查 `rate_by_style`；校验通过窗口是 `±max(10%, 3秒÷目标时长)`（15 秒档因此是 ±20%，
不是 ±10%），这个阈值目前**不能按包配**。

**占位符**用 `$var` 语法（`$topic` `$platform` `$quota_total` `$topics_slice`…全表见 skill.yaml 头部注释）。
模板里的 `{ }` 花括号原样保留，写 JSON 示例不受影响。

**注入文件只取需要的那一节**：`stages.<阶段>.files` 的取值支持 `路径#章节关键词`，

```yaml
files:
  growth: patterns/growth.md                  # 整份
  terms: knowledge/standards.md#核心术语        # 只取这一节（427 字 vs 整份 2195）
```

**`#章节` 找不到时返回空串，不退回整份**（`app/knowledge.py:431-454`，与上面 `slice_heading`
的"退整份"相反，故意的）：写了 `#章节` 就是明确说"只要这一节"，这时灌整份恰好是要避免的。
代价是"章节被改名 → 这节知识静默消失"，所以有一条静态对账测试兜着
（`tests/test_prompt_templates.py::test_declared_stage_files_are_actually_found`）——
**改了 md 的标题就要同时改 `skill.yaml` 里的 `#章节`**，否则测试报红。
`$hooks` 是例外：**由引擎按风格切片**（`Pack.hooks_slice`），select.files 里不必、
也不应再声明 —— 一份 hooks.md 里 5 套语气模板，每轮只用得上当前风格那一套；
风格名对不上时 hooks **会**退回整份（这是 `hooks_slice` 与 `file_slice` 的另一处不同）。

## 三、知识库内容怎么来（四条路）

### 路线 1：向导生成（最快起步）
**设置 → 生成偏好 → 行业包卡「新建」** → 输入行业名 + 一句话业务描述 → 模型按模板包同结构生成初稿。
它是一条**后台作业**（「行业包生成中」，与其它作业共用并发额度），可取消、失败会写进常驻错误横幅；
**目录已存在**同名时同步 409（不起必然失败的作业）；但若两个同名请求同时**正在创建中**，
第二个要等第一次模型调用跑完才被判失败（互斥锁取在调用之后，`app/packgen.py:165-171`）。
生成包为**草稿态**（界面有角标），结果页给产物摘要与校对清单，
清单里还并入了引擎的**自体检**结果（加载是否成功、切片/配额/词表有没有降级）——
逐项核实后在包详情点「标记为已校对」（等价于把 `pack.yaml` 的 `draft: true` 改为 `false`）。
**注意**：向导不生成任何标准/法规编号（防编造），需人工补录。

⚠ 新包会**原样带上模板包的 `patterns/growth.md`、`hooks.md`、`knowledge/voice.md`** ——
目前模板回退到电梯包，`growth.md` 的标题就叫「电梯口播特有的取舍」，而它**每轮撰写都注入**。
换行业必须逐份改写成本行业内容，否则模型收到的是别行业的完播建议。

### 路线 2：复制改造（最可控）
复制 `packs/elevator/` 改名，替换 knowledge/ 内容、改 pack.yaml 的参数与映射。
适合：与电梯行业知识结构相近的行业。
**必做**：删掉 `private/*.yaml` 里的示例条目（不要留着写"示例："—— 整条目级的示例剔不掉，
会以【私有知识库（优先作为事实来源）】的名义每轮注入模型）。

### 路线 3：手写（质量最高）
按上面目录结构从零写。写作规范：
- **能用数字的绝不写形容词**（"响应快" → "市区 2 小时内到场"）
- 每个细分领域配**常见误区表**（误区=现成的反常识选题）
- 每条参数带 `source` 与 `verified` 日期（private/ 资料尤其）
- 标准编号**只写核实过的**，没核实的写名称

### 路线 4：私有资料注入（差异化壁垒）
`private/*.yaml` 四个模板：products（型号参数）/ service（服务承诺）/ cases（完工案例）/ faq（异议应答）。
- 手工填写，**只填做得到、愿意公开承诺的**；留空的字段引擎自动走占位符
- 每条带 `source` + `verified`，且**只写你真正核实过的**：引擎不会检查这两个字段，
  空着或编一个都会被模型当成既成事实引用（它们以【私有知识库（优先作为事实来源）】注入）
- `cases.yaml` 里 `public: false` 的案例自动模糊化为"XX市某小区"
- `private/raw/` 是原始资料投放区（预留）：当前版本请把要点按模板整理进上层 yaml，
  或贴给任意 AI 助手按模板结构化后粘回

### 内容质量的自检口诀

## 五、导出为 Agent 技能（给别的 agent 用）

> ⚠ **界面上没有这个入口了**（2026-09-17 撤：一个用一次就忘的动作，占着包详情最显眼的位置）。
> 能力本身在后端，手工调用端点即可：

```bash
# 令牌是引擎启动时打印的那个，走请求头
curl -X POST "http://127.0.0.1:<端口>/api/packs/elevator/export-skill" \
     -H "X-TalkScript-Token: <令牌>"
# 带上才导出 private/（默认不带 = 私有资料不外带）：  ?include_private=true
```

产物落在 `agent-skills/<行业>/`，是一份**文件型技能目录**：

```
agent-skills/<行业>/
├── SKILL.md          # 技能入口：角色、参数表、五步流程、硬约束（由 skill.yaml + pack.yaml 自动组装）
├── tools/check.py    # 独立校验器（字数/时长/禁用词，无需安装本引擎即可运行）
├── knowledge/ patterns/ rules/ compliance/   # 知识与规则原样复制
└── banwords.yaml  pack.yaml  skill.yaml      # private/ 仅在显式开启时出现
```

**使用方法**：把整个目录复制到目标 agent 的技能目录——
WorkBuddy：`C:\Users\<你>\.workbuddy\skills\`；ZCode：`~/.zcode/skills`；Claude Code：`~/.claude/skills`。

之后在该 agent 里说"写一条困人科普"之类的话，agent 会按 SKILL.md 的流程生成脚本，
并调用目录里的 `tools/check.py` 做字数与禁用词校验（校验器是引擎同款独立副本）。

**注意**：
- 引擎桌面应用和导出技能是两种运行形态：前者有自动回炉/历史/界面，后者靠 agent 自觉执行流程
- 导出的是**当时那份包**；改了包要再调一次端点才会刷新（没有增量同步）
- 导出技能里的分镜口径与引擎一致：`tools/check.py` 只校验口播正文，分镜要靠 agent 自觉
