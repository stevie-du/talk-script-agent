# 知识库与技能配置指南

> 准备知识库内容（不管交给谁处理）所需的**内容格式规范与 AI 整理指令**，
> 见 **[知识库内容规范.md](知识库内容规范.md)**（含可直接复制给任何 AI 的提示词模板）。

TalkScript 是**通用**的口播脚本生成器：引擎不认识任何行业，每个行业是一个**行业包**（`packs/<行业>/`）。
一个包 = 四样东西：

| 组成 | 位置 | 回答的问题 |
|---|---|---|
| **知识库** | `knowledge/` | 写什么（行业知识点、受众痛点、选题） |
| **技能** | `skill.yaml` | 怎么写（各阶段提示词、注入哪些文件、回炉几次） |
| **合规词表** | `banwords.yaml` + `compliance/` | 什么不能写 |
| **私有资料** | `private/` | 你独有的事实（型号、报价逻辑、案例） |

**分享一个行业给同事 = 复制这个目录**（不含 `private/` 即不带商业信息）。

---

## 一、知识库怎么配置

### 目录结构与分工

```
packs/<行业>/
├── pack.yaml            # 清单：参数选项/默认值、语速、字数配额、章节映射、私有资料路径
                         #   ⚠ 这个文件里的**注释是文档的一部分**（字段含义都写在那里）：
                         #   界面上的「标记为已校对」只就地改 `draft:` 那一行，
                         #   不会再把整份文件 safe_dump 回去吃掉注释
├── skill.yaml           # 技能（见第二节）：**哪个阶段注入哪些文件写在这里，不写在 pack.yaml**
├── banwords.yaml        # 禁用词：hard（必改）/ soft（提示）× 平台 extra_hard / demote / promote
├── ai_tells.yaml        # 人味 tell 词表（**不注入提示词**，只被校验器读）：
                         #   strong/weak 两个 tell 名单 + lexicon 词类 + md 指向清单文档
├── knowledge/
│   ├── topics.md        # 按细分领域分章（## N. 章节名），每章：核心知识点/常见误区表/需占位事实
│   ├── audience.md      # 按受众分章，每章：深层恐惧/高频疑问/推荐CTA
│   ├── ideas.md         # 选题库（`## 选题库` 一节注入：select 与 draft 两个阶段都注；公式/禁忌是人读）
│   ├── standards.md     # 标准/法规索引（只写已核实的编号！；`## 核心术语` 一节可被注入）
│   └── voice.md         # 口语化与人设声音（人味档位注入）
├── patterns/
│   ├── hooks.md         # 钩子库（10 类）与风格模板 —— 选题阶段按风格切片注入
│   ├── growth.md        # 完播率/转化率要点 —— 撰写阶段注入
│   └── anti-ai-smell.md # AI 味自查清单 —— 人味档位注入
├── rules/               # 时长配额与输出模板（两份都是人读约定，不注入模型）
├── compliance/          # 广告法/平台规则/行业红线（红线经 select+write 的 files.redlines
│                        #   注入，且只取 `compliance/industry.md#红线速查` 那一节）
└── private/             # 私有资料（见第四节）—— **界面里读不到，只能开本地文件改**

packs/_template/         # ⚠ **不是行业包**：向导建包用的骨架（`packgen.TEMPLATE_PACK`）。
                         #   以 `_` 开头 → list_packs 跳过它，界面选不到。
                         #   它会被复制进每一个新包，所以**一条行业事实都不许有**
                         #   （patterns/hooks|growth、knowledge/voice、private/* 四份 yaml…）
```

> **这个目录在打包版住在哪里**：`%APPDATA%\TalkScript\packs\<行业>\`，
> 不是安装目录。安装包里那份 `resources\engine\packs` 只是**首次运行用的只读种子**：
> 没改过的包会随应用更新同步过来，改过的包保持你的那份、只在日志里提醒一句
> （`app/packseed.py`）。所以「手改了包却没生效」先确认改的是数据目录那一份；
> 界面路径显示在 `/api/meta` 的 `packs_dir` 里。开发态仍是仓库根 `packs/`。

### 两套"切片"机制，别混

| 机制 | 由谁决定 | 找不到时 |
|---|---|---|
| **哪些文件进哪个阶段** | `skill.yaml` 的 `stages.<阶段>.files`（**`pack.yaml` 里的 `files.select/write/...` 引擎不读**，只有 `files.private` 是活的） | 文件不存在 → 该占位符为空 |
| **一份文件里取哪一章** | 参数值 → `pack.yaml` 的 `topics_map` / `audience_map` → 章节标题关键词 | 见下面两行的区别 |

降级方向两份文件**不一样**（`app/knowledge.py` 的 `Pack.audience_slice()` / `slice_heading()`），照下表写才不会踩坑：

| 情况 | `topics_map`（细分领域） | `audience_map`（受众） |
|---|---|---|
| 参数值不在映射里 | 退到映射里名为「通用」的那一章 | **返回空串**（不注入整份） |
| 连「通用」都没有 / 映射值为空 | 返回**整份文件** | — |
| 映射到了，但那个章节名在文件里找不到 | 返回**整份文件** | 返回**整份文件** |

所以：**章节名写错 = 静默灌整份**，整份里别的章节会把模型注意力带走；
这一类降级由 `param_audit` 报出（第四节），不会在生成时报错。
匹配是**子串**匹配：`## 2. 旧楼加装` 用关键词 `旧楼加装`、`加装` 都能命中，
不必与标题逐字相同（电梯包就有意利用这一点：`行业观察` → `## 行业趋势`）。

### 映射怎么写

知识文件**不会全量**塞给模型，靠下面这两张映射表切到章：

```yaml
topics_map:            # 参数值 → topics.md 的章节标题关键词
  旧楼加装: 旧楼加装
  维保: 维保
audience_map:          # 参数值 → audience.md 的章节标题关键词
  业主乘客: 业主乘客
```

用户选了「旧楼加装」→ 引擎只取 `topics.md` 里含"旧楼加装"的那个 `##` 章。
**新建包时保证每个参数选项都在映射表里、关键词能命中一个真实章节** ——
上面那张降级表里的三种"退整份/退空"都是静默的，只在设置页的包体检里能看到。

### 格式规范（每个文件谁在读、要求什么）

**严格格式（引擎结构化解析，写错即失效）：**

| 文件 | 格式要求 |
|---|---|
| `pack.yaml` | 引擎真读的字段（**完整清单**）：`display_name`、`draft`、`description`、`params.<名>.{options,default}`、`topics_map`、`audience_map`、`rate_by_style`、`quota_table`（每项固定 `total/hook/body/cta` 四键）、`points_by_duration`、`banwords`（词表文件名）、`files.private`、`rewrite_scope`（回炉范围三档，见下）、`duration_tolerance_pct`（时长容差）、`intel_sources`（情报源声明，见《需求方案-去AI味与热点情报》§2.2）；`params.*.label` 只有渲染层读、`name` 只进产物的 pack 字段 —— **取包用的是目录名**（`Pack(root, name)`），两者不一致时产物能看但不能「重写本段」。`version` 目前是纯声明（解析但不消费）。**上面没列的键写了也不会被读**：`files.select/write/compliance/facts` 这类"看着像配置"的死键已于 2026-09-20 删除 |
| `skill.yaml` | `$占位符` 语法见文件头注释；`stages` 五段：`select` / `draft` / `write` / `storyboard` / `rewrite_segment`（`draft` 在 select 与 write 之间 —— 文档原写四段，漏了它）（缺 `storyboard` 的包会被跳过并留痕，不报错）；`anti_ai.levels` 固定 strong/standard/off 三档；`limits.recheck_rounds` = 校验不过时的回炉次数 |
| `ai_tells.yaml` | 顶层 `strong:` / `weak:` 列 tell 名（名不在 `app/ai_tells.py` 的 `AITells.ALL` 里 → 报进 `config_warnings`，不会静默不跑）；`lexicon:` 只给**词表类** tell 供词，**单字无效**（`len>=2` 过滤，与 `MIN_WORD_LEN` 同口径：要拦「性/度/化」就写「高效性/舒适度/智能化」）。判定**不进 `passed`** —— 一把没校准的尺子不该拦发布。文件不存在 = 这个包不做文风检测（报告里 `check.ai_tells` 为 null，**不是** 100 分） |
| `banwords.yaml` | `hard:` / `soft:` 为字符串列表；`platform.<平台>` 下**只认** `extra_hard` / `promote` / `demote` 三种键 —— 写 `extra_soft` 不报错也不生效。**不要写单字条目**（见下） |
| `private/*.yaml` | 合法 YAML，字段名按模板；引擎只剥**含 `示例：` 的字符串叶子**：一条里若还有别的值，就带着那些值留下来（于是出现"只有一条 `type: 加装`"的空壳案例）；全是示例值的条目会变成 `{}` 而整条消失。所以未填的条目请**整条删掉**而不是留着写"示例："；留空字段自动走占位符 |

> **⚠️ `stages.<阶段>.files` 的 key 必须与模板里的占位符同名。**
> 例：`write.files: {growth: patterns/growth.md}` 对应模板里写 `$growth`；
> 写成 `$growth_block` 不会报错（`Template.safe_substitute` 对未知变量保持原样），
> 但**文件不会被注入**，模型还会收到一段字面量 `$growth_block`。
> 引擎现在会检测未填充的占位符并记进作业「日志」页签，改完包记得看一眼。

> **⚠️ 禁用词表不要写单字条目**（如 `最`）：它会命中「最近」「最后」「最好」这类
> 正常用词，噪声远大于收益。要拦绝对化表述请写具体短语（`最低价` / `最便宜`）。
> 引擎会忽略单字条目，并在生成结果的合规区说明忽略了哪些。
> 另外命中判定是**不重叠**的：`包过检` 只算 1 处（归属给最长的词）。

**知识正文（模型上下文，格式自由但强烈推荐以下结构）：**

`topics.md` 每章三件套——核心知识点（带数字）、误区表、需占位事实：

```markdown
## 2. 旧楼加装

### 核心知识点
- 底坑深度与顶层高度是能否加装的两大硬条件
- 管线迁改常是预算超支主因

### 常见误区
| 误区 | 事实 |
|---|---|
| 一楼一定反对 | 关键在补偿方案与沟通 |

### 需占位的事实
本地造价区间、补贴标准 → {{待补}}
```

`audience.md` 每章：深层恐惧（顿号短语）/ 高频疑问（列表）/ 推荐 CTA。
钩子库 `patterns/hooks.md` 必须含类型表（选题阶段要求 hook_type 从中选），
并且按 `## 一、钩子库…` + `### <风格名>`（风格名与 `pack.yaml` 的 style 选项一致）
两级的结构写 —— 引擎按风格只注入当前那一套（`Pack.hooks_slice`）。

**消费关系（诚实说明，避免无效劳动）：**
- 引擎**生成时真读**的：`topics.md`/`audience.md` 对应章节、`hooks.md`、`growth.md`、
  `voice.md`、`anti-ai-smell.md`、`knowledge/ideas.md`（**只注 `## 选题库` 那一节**，
  select 与 draft 两个阶段都注 —— 声明了 draft 段的包由 draft 消费，未声明的老包由
  select 消费）、`compliance/industry.md`（**只注 `## 红线速查` 那一节**，选题与撰写同源）、
  `private/*.yaml`、`banwords.yaml`、`pack.yaml`、`skill.yaml`
  —— 注入清单以 `skill.yaml` 的 `stages.<阶段>.files` 为准：**没写进去的文件引擎不看**
- **人 / agent 参考**用、生成时不注入的：`ideas.md` 的「选题公式 / 挖选题姿势 / 禁忌选题」三节、
  `standards.md` 的法规编号部分（人工核对；只有 `## 核心术语` 一节按 `write.files.terms` 注入）、
  `compliance/industry.md` 的 §1~§8 细则（可执行口径已浓缩进「红线速查」）、
  `compliance/ad-law.md`/`platform.md`（细则，硬约束由 banwords 校验执行）、
  `rules/duration.md`（时长与语速的推导过程；实际取值走 `pack.yaml` 的
  `rate_by_style`/`quota_table`/`points_by_duration`）、
  `rules/output-template.md`（给人看的排版样式；模型输出的结构契约在 skill.yaml）
- 这些文件分享包给同事时原样跟包走（对方照 `output-template.md` 的版式人工交付）
- ✅ **孤儿文件有测试替你报警**：`tests/test_pack_orphan_files.py` 会扫每个包目录里的 `.md`，
  要求它要么被 `skill.yaml`（或引擎按约定加载的 `topics/audience/hooks` 三份）接上，
  要么登记在测试里那份"给人看"清单中并写明给谁看。新增一份没接线的 md → 测试红；
  把某个文件接进提示词之后忘了从清单里删 → 也红（清单只作减法）。
  电梯包现在登记在清单里的是 4 份有意的人读物：`ad-law.md`、`platform.md`、
  `rules/duration.md`、`rules/output-template.md`。离线验一眼渲染结果（不发请求、不落盘）：

  ```bash
  .venv/Scripts/python.exe -c "import sys;sys.path.insert(0,'.')
  from pathlib import Path;from app.knowledge import Pack;from app.prompts import PromptRenderer
  pk=Pack(Path('.').resolve(),'elevator');pr=PromptRenderer(pk)
  # 用 app/pipeline.py 里同款的 ctx 构造参数，或直接打印 pr.file_text / Pack.file_slice 的返回值
  print(len(pk.file_slice('compliance/industry.md')), len(pk.file_slice('knowledge/standards.md#核心术语')))"
  ```

  返回 0 就说明这条 `files` 声明其实注入不到东西（章节名对不上是**静默**的，
  只有 `tests/test_prompt_templates.py` 的那条对账测试会报红）。
  另一个信号是作业日志里出现 `tpl_<阶段>`「模板占位符未填充」 —— 它说明
  `files` 的 key 与模板里的 `$占位符` 名字不一致，知识同样没进去。

### 新增一个细分领域的步骤

1. `pack.yaml` → `params.segment.options` 加一项（如 `板材环保`）
2. `topics_map` 加映射 `板材环保: 板材环保`
3. `knowledge/topics.md` 加 `## N. 板材环保` 章节（核心知识点 + 误区表 + 需占位事实）
4. `knowledge/ideas.md` 补几条该细分的选题

## 二、技能（skill.yaml）怎么配置

技能 = **生成方法**。改它就能让同一份知识库写出不同风格的稿子。

```yaml
limits:
  recheck_rounds: 2        # 校验不合格自动回炉次数
stages:
  select:                  # 选题阶段：system + user_template + 注入文件
  draft:                   # 起草阶段（select 之后、write 之前）
  write:                   # 撰写阶段：含 anti_ai（人味三档的规则与注入文件）；只出 sections
  storyboard:              # 分镜阶段：正文校验通过后单独跑一次（format=voice 时整个跳过）
  rewrite_segment:         # 单段重写阶段
```

阶段顺序固定为 select → (write ⇄ check) → storyboard → done。分镜单独成阶段是为了
省钱与省时：画面描述的字数与口播同量级，并给 write 会让**那一次调用**的输出与思考量成倍上涨
（电梯包实测 110~127s → 12~23s，注意那是单次撰写调用的数字，端到端还要加回分镜这一次调用），
更关键的是**回炉的每一轮不再连带重画分镜**。缺 `storyboard` 阶段的旧包会被**跳过并留痕**
（日志 `storyboard_skip`），不会让已经写完的正文以失败收场。

两条要知道的不对称（都是当前实现的真实行为）：
- **生成路径**上分镜调用失败 = 整条作业判 `failed`，哪怕正文刚通过校验；
  **单段重写**路径相反 —— 重画失败只留痕、沿用旧分镜（`app/pipeline.py`：生成主路径 vs `_run_rewrite_segment`）。
- 模型返回的 `time` **不校验也不覆写**：时间轴虽由引擎算好后写进提示词，但产物里仍以模型给的
  `time` 为准、算出的 `timings` 兜底，段数不符只记一条 `storyboard_mismatch`。

**常见改法**：

| 想要 | 改哪里 |
|---|---|
| 语气更收敛 | write.system 里的口语化规则，收紧第 7 条 |
| 更强反 AI 味 | anti_ai.rule 加严 + levels.strong.files 增加范文文件 |
| 不同行业不同写法 | 每个包一份 skill.yaml，互不影响 |
| 回炉更严格 | limits.recheck_rounds 调大（每多一次多一次模型调用） |
| 换注入的知识文件 | stages.write.anti_ai.levels.*.files 增删路径（不存在的文件自动跳过） |

**各阶段的输出预算不在 skill.yaml 里**，写死在引擎：选题 4000、分镜 4000、单段重写 3000，
只有撰写用配置里的 `llm.max_tokens`（`app/pipeline.py`，包作者改不了）。
包能影响的是**配额与容差**：字数配额查 `quota_table`、要点数查 `points_by_duration`、
语速查 `rate_by_style`；校验通过窗口默认 `±max(10%, 3秒÷目标时长)`（15 秒档因此是 ±20%，
不是 ±10%），要按包覆盖就写 `duration_tolerance_pct: 15`（合法 0.5~100；写错 = 包的
`pack_error`，生成被 409 拦住，不会带着坏值去判定）。本次真正生效的那个值会随报告外发
（`check.tolerance_pct`），所以回炉反馈与校验结论不可能各说一套。

**占位符**用 `$var` 语法（`$topic` `$platform` `$quota_total` `$topics_slice`…全表见 skill.yaml 头部注释）。
模板里的 `{ }` 花括号原样保留，写 JSON 示例不受影响。

**注入文件只取需要的那一节**：`stages.<阶段>.files` 的取值支持 `路径#章节关键词`，

```yaml
files:
  growth: patterns/growth.md                  # 整份
  terms: knowledge/standards.md#核心术语        # 只取这一节（427 字 vs 整份 2195）
  redlines: compliance/industry.md#红线速查     # 选题与撰写同源（798 字 vs 整份 2957）
  ideas: knowledge/ideas.md#选题库             # 只注选题那一节（2293 字 vs 整份 3337）
```

**`#章节` 找不到时返回空串，不退回整份**（`app/knowledge.py` 的 `Pack.file_slice`，
与上面 `slice_heading` 的"退整份"相反，故意的）：写了 `#章节` 就是明确说"只要这一节"，
这时灌整份恰好是要避免的。代价是"章节被改名 → 这节知识静默消失"，所以有一条静态对账测试兜着
（`tests/test_prompt_templates.py::test_declared_stage_files_are_actually_found`）——
**改了 md 的标题就要同时改 `skill.yaml` 里的 `#章节`**，否则测试报红。
⚠ 仓库里那条测试只跑 `list_packs()` 看得见的包，**向导生成的草稿包不在其中**：
`#红线速查` / `#选题库` / `#核心术语` 三个标题由 `app/packgen.py` 的 `_materialize` 写进新包，
改模板包的标题就要同时改 packgen（这条由 `tests/test_template_pack.py` 的切片断言兜住，
生成时的 `_pack_audit` 也会把"章节切片为空"列进校对清单）。
`$hooks` 是例外：**由引擎按风格切片**（`Pack.hooks_slice`），select.files 里不必、
也不应再声明 —— 一份 hooks.md 里 5 套语气模板，每轮只用得上当前风格那一套；
风格名对不上时 hooks **会**退回整份（这是 `hooks_slice` 与 `file_slice` 的另一处不同）。

**回炉反馈必须放在用户提示词的末尾（前缀缓存）**：`$feedback_block` 是撰写阶段
**每轮唯一变化**的内容。DeepSeek 式前缀缓存命中的是「与上一次请求完全相同的最长前缀」，
所以它原先排在第 2 行时，回炉的每一轮都会把前面整段静态提示词判为未命中
（多付一遍 token、更慢）。现在它在末尾：60 秒档实测首轮 7162 字、次轮 7213 字，
**共同前缀 7162 字 = 整段静态部分**。改模板时请把静态体放前、动态块（`$feedback_block`）放最后，
这条由 `tests/test_pack_injection.py::test_feedback_block_sits_at_the_end_so_the_prefix_is_stable` 钉住。

## 三、知识库内容怎么来（四条路）

### 路线 1：向导生成（最快起步）
**设置 → 生成偏好 → 行业包卡「新建」** → 输入行业名 + 一句话业务描述 → 模型按模板包同结构生成初稿。
它是一条**后台作业**（「行业包生成中」，与其它作业共用并发额度），可取消、失败会写进常驻错误横幅；
**取消或失败的建包会收走本次刚写出的那个目录**（只允许动 `packs/<这一次的名字>`），
所以界面上说"已取消/失败"与下一次同名提交报「行业包已存在」不会同时成立；
回收**没**做成时（目录被别的程序占着）会在作业里明写一步「本次目录未能回收：请手动删除
packs/<slug>」—— 应用里没有删包的入口，不写出来用户就没有下一步。
**判"这个包坏了"之前引擎会先重读**（`packgen._RELOAD_WAITS`）：Windows 上刚落盘的
`pack.yaml` 常被杀毒软件/搜索索引按住几百毫秒，此刻读到的是 `PermissionError`，
而它和"模型真写坏了文件"在异常类型上完全同形。老形状会把用户付过钱的整包删掉，
还会建议"换个更具体的业务描述"。同理，**读不出字节的错误不进进程级 YAML 缓存**
（缓存键是 mtime/size，读失败时这两位都没变 —— 进去过一次就把好包钉成坏的直到重启）。
**目录已存在**同名时同步 409（不起必然失败的作业）；两个同名请求**同时**提交时，第二个也是
同步 409「行业包正在创建中」—— 占位在 `Pipeline.start_packgen` 里、**取在模型调用之前**
（`app/packgen.claim_slug`），一分钱都不会花。早先"锁取在调用之后、第二个要等第一次跑完才判失败"
的形态已经修掉了。
生成包为**草稿态**（界面有角标），结果页给产物摘要与校对清单，
清单里还并入了引擎的**自体检**结果（加载是否成功、切片/配额/词表有没有降级）——
逐项核实后在包详情点「标记为已校对」（等价于把 `pack.yaml` 的 `draft: true` 改为 `false`；
它是**行内改写**那一行，不会像早先那样用 `yaml.safe_dump` 把整份文件重排一遍、
连带把注释全删掉）。
**注意**：向导不生成任何标准/法规编号（防编造），需人工补录。

模板回退已经删掉了：现在**只有** `packs/_template/` 一份模板，缺目录或缺其中任何一个
骨架文件，建包直接失败（`TemplateMissingError`），不会再"成功地"产出一个带着
别的行业事实的包。`_template` 以 `_` 开头 → `list_packs` 跳过它，界面上选不到。

⚠ 新包会**原样带上模板包的 `patterns/growth.md`、`patterns/hooks.md`、`knowledge/voice.md`、
`patterns/anti-ai-smell.md`** 与**全空白的 `private/*.yaml`** —— 模板包里不含任何行业事实
（`tests/test_template_pack.py` 逐文件 grep 钉住），所以新包的这些内容是**通用骨架**：
它们**每轮都注入**，留着不改不会写错，但也不像你说的行业。校对清单里逐项列出了要填的位置。
`private/` 不填 = 没有任何私有事实可注入（模型只会写 `{{待补：xxx}}` 占位）。

### 路线 2：复制改造（最可控）
两条路：复制 `packs/elevator/`（与它知识结构相近的行业最省事），或复制 `packs/_template/`
再改名（从零开始、不带任何行业事实）。注意 `_template` 里的 `knowledge/{topics,audience,ideas,standards}.md`
与 `compliance/industry.md` 是**空缺的**（那几份由向导生成或自己写），其余骨架文件齐全。
**必做**：删掉 `private/*.yaml` 里的示例条目（不要留着写"示例："—— 整条目级的示例剔不掉，
会以【私有知识库（优先作为事实来源）】的名义每轮注入模型）。

### 路线 3：手写（质量最高）
按上面目录结构从零写。写作规范：
- **能用数字的绝不写形容词**（"响应快" → "市区 2 小时内到场"）
- 每个细分领域配**常见误区表**（误区=现成的反常识选题）
- 每条参数带 `source` 与 `verified` 日期（private/ 资料尤其）
- 标准编号**只写核实过的**，没核实的写名称

### 路线 4：私有资料注入（差异化壁垒）
`private/*.yaml` 四个模板：products（型号参数）/ service（服务承诺）/ cases（完工案例）/ faq（异议应答）。
- 手工填写，**只填做得到、愿意公开承诺的**；留空的字段引擎自动走占位符
- 每条带 `source` + `verified`，且**只写你真正核实过的**：引擎不会检查这两个字段，
  空着或编一个都会被模型当成既成事实引用（它们以【私有知识库（优先作为事实来源）】注入）
- `cases.yaml` 里 `public: false` 的案例自动模糊化为"XX市某小区"
- `private/raw/` 是原始资料投放区（预留）：当前版本请把要点按模板整理进上层 yaml，
  或贴给任意 AI 助手按模板结构化后粘回
- **`private/` 下的文件不经界面预览**：设置 → 行业包 的列表里看得到文件名与体积，
  点开却是 `403 私有资料不经界面浏览…`。这是与「安装包不带 private/」同一个立场（`GET /api/packs/{name}/file` 里那条判断）——
  要看要改就打开本地文件：`<数据目录>\packs\<行业>\private\`。
  生成时引擎照常读它们并注入，这条限制**只作用于 HTTP 这道口**。

### 内容质量的自检口诀

> 知识库决定脚本的下限。生成结果"合规但空洞"，先检查 knowledge/ 是否有具体数字、
> 误区表和真实场景；再检查 private/ 是否还是空模板。

## 四、验证你的配置

1. **设置 → 生成偏好 → 行业包卡「详情」**：看文件清单、草稿状态，以及引擎对该包的
   体检结论（`param_audit`：哪个参数值切不到章节、配额是否退化、词表是否被降级）
2. mock 模式跑一遍流程（`TALKSCRIPT_MOCK=1`）验证结构无误
3. 真实生成 1 条，看「日志」页签有没有 `tpl_<阶段>`（占位符没填上=知识没进去）、
   `storyboard_skip` / `storyboard_mismatch`（分镜没画或段数不符）
4. 跑一遍与包有关的守卫测试（改包必跑）：

   ```bash
   .venv/Scripts/python.exe -m pytest tests/test_prompt_templates.py \
       tests/test_pack_yaml_integrity.py tests/test_banwords_alignment.py \
       tests/test_pack_injection.py tests/test_template_pack.py
   ```

   它们守的是：声明的 `files`/`#章节` 真能取到内容、`pack.yaml` 结构与 quota 一致、
   `compliance/ad-law.md` 的词族在 `banwords.yaml` 里有着落、
   **选题阶段确实带红线与选题库**且**回炉块排在末尾**（`test_pack_injection.py`）、
   **模板包不含任何行业事实且缺失时建包直接失败**（`test_template_pack.py`）。
   ⚠ 词族对账那条只逐行解析**以固定前缀开头**的词族行（`test_banwords_alignment.py:22-25`），
   且判定是"子串互含" —— 它挡得住"文档加了词族而词表没跟上"，
   挡不住"词表删了词而文档还在推荐它"，也挡不住整份 md 有没有被注入
5. 新建包在生成完成后自带体检结果（上面第 1 步那套检查），不用等第一次生成
