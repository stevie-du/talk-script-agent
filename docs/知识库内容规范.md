# 知识库内容规范（含给任何 AI 的整理指令）

> 这份规范与工具无关：不管是让 TalkScript 的我处理、把资料丢给 ChatGPT/Kimi/豆包 整理、
> 还是自己手写——照此规范产出，都能直接导入行业包。
> 导入后的使用与校验流程见 [知识库与技能配置指南.md](知识库与技能配置指南.md)。

## 一、快速上手（三种用法）

| 用法 | 做法 |
|---|---|
| 让 TalkScript 的我处理 | 配好 API Key 后，把资料丢进对话说"按知识库规范整理成 XX 行业包"，我用向导+规范直接生成 |
| **给别的 AI 处理（本文重点）** | 复制第三节的大提示词 → 填两个空 → 连同你的资料发给任何 AI → 按第五节导入 |
| 自己手写 | 按第二节的格式模板逐文件撰写 |

**先复制一份结构骨架**：把 `packs/elevator/` 整个目录复制改名（这就是你的新行业包），
AI 产出的内容稍后**覆盖其中对应文件**——结构文件（skill.yaml、patterns、rules、compliance 通用部分）
不用重写。

> ⚠ **复制完立刻删掉 `private/`**（2026-09-27 补）—— 这一步不做，
> 你这个新行业包**每生成一条脚本都会注入电梯的话术**。
>
> `private/` 是电梯包自带的私有知识库（`pack.yaml` 的 `files.private` 声明了它，
> 引擎**每轮都注入**），里面是电梯行业的东西：机型分类、维保周期、
> 「后期维护贵不贵 → 给周期和构成：**维保费、年检费**、电费、易损件更换」
> 这类异议应答。照原样留着，你的口腔诊所包会一本正经地说「维保费、年检费」。
>
> 删掉之后你的包就没有私有知识库了（引擎会照常跑，只是没有差异化素材）。
> 想加回来：建一个**空的** `private/`，照 `packs/_template/private/README.md`
> 那份模板的字段填自己的东西（模板里全是空值，不带任何行业内容）。
> 不确定怎么填就先别建 —— 空着比填错安全得多。

## 二、格式规范（每个文件的要求）

**铁律（适用于所有文件）**：
1. 能用数字的绝不写形容词（"响应快" → "市区 2 小时内到场"）
2. 标准/法规**编号**、具体数据：没有可靠来源就**不写**，列进"待核实清单"——编一个错编号比不写危险十倍
3. 禁止绝对化用语：最 / 第一 / 绝对 / 100% / 永不 / 政府补贴类权威背书
4. 每个细分领域必须有**常见误区表**（每条误区都是一个现成的反常识选题）
5. 章节标题（`## N. XXX` 的 XXX）必须能被 `pack.yaml` 映射表里的关键词** substring 命中**
   （`topics_map` / `audience_map` 的值是标题里的关键词，不必逐字相同）；
   命中不到会退回整份文件注入，等于把别的受众/细分的内容一起塞给模型

### knowledge/topics.md（每个细分领域一章）

```markdown
## 1. 章节名（= 参数选项，逐字一致）

### 核心知识点
- 3~6 条，每条一个可讲的具体知识点，优先带数字/对比/流程

### 常见误区
| 误区 | 事实 |
|---|---|
| 用户普遍以为的错法 | 一句纠正（具体、可讲） |

### 需占位的事实
本地价格区间、品牌专属数据等 → 由用户填 {{待补}}
```

### knowledge/audience.md（每类受众一章）

```markdown
## 1. 受众名（= 参数选项）

### 深层恐惧（痛点）
、顿号短语 4~6 个

### 高频疑问（选题金矿）
- 8~10 条用户真实会问的问题

### 推荐 CTA
一句话（评论关键词 / 领资料 / 预约……）
```

### knowledge/ideas.md
≥ 30 条编号选题，格式：`编号. 标题 — 钩子类型`。**破折号后面的钩子类型不能省**。

**`## 选题库` 那一节会被注入模型**（两个阶段都在注：`skill.yaml` 的
`select.files.ideas` 与 `draft.files.ideas` 都指向 `knowledge/ideas.md#选题库`；
声明了 `draft` 段的包——含默认 elevator——选题与正文一次调用，ideas 由 draft
阶段消费，未声明 `draft` 的老包由 select 阶段消费）—— 它同时是"给人挑主题的清单"
和"给模型的选题池"，所以条目要按选题契约写（`angle` / `hook_type` / `audience` /
要点方向 / CTA 方向，见该文件头部说明）。
文件里 `## 选题公式`、`## 挖选题的正确姿势`、`## 禁忌选题` 三节自己标了「不注入」，
切片按 `#选题库` 取，不会进去。

> ⚠ **钩子类型是必填项，不是可选标注**（2026-09-27 更正，原文写的是
> `编号. 标题角度`）。那一节进的是**选题阶段的提示词**，模型的 `hook_type` 得
> 从条目里读；少了破折号那段，模型就只能自己编一个钩子类型 ——
> 那样它多半会退回到「权威科普 / 清单钩子」这类**风格名**（不是钩子）。
> `tests/test_pack_injection.py` 正是按"每条选题行必须含破折号、破折号后必须是
> `patterns/hooks.md` 那 10 类之一"来守的：照旧格式写出来的包会被它挡下。
>
> 一行长这样（缺受众标注时就是"标题 — 类型"两段）：
> ```
> 1. 进电梯先看这个标志，过期一天都别坐 — 直接痛点
> 12. 老楼加装到底卡在哪一步 — 业主乘客 · 损失厌恶
> ```
> 受众那一段只能写 `pack.yaml` 的 `audience` 选项名（不写就用该节 `受众默认`）。

### knowledge/standards.md
只列"需人工核实的标准/法规/政策**名称**"，**不写编号**（编号必须人工核实后补）。
其中 `## 核心术语` 一节会被撰写阶段按 `write.files.terms` 注入 —— 术语请写在这一节里。

### compliance/industry.md
行业特有红线 5~8 条（广告法之外的），每条一句可执行的禁令。
**这份会被注入**（撰写阶段每轮的【行业红线】），所以它是最值钱的合规资产；
统一口径（如救援话术）、术语规范、禁演清单都该写在这里，而不是写在 `platform.md`。

### 禁用词增补（追加进 banwords.yaml）
只写 `hard` / `soft` 两个顶层列表；平台级差异只认 `platform.<平台>` 下的
`extra_hard` / `promote` / `demote` —— **引擎不读 `extra_soft`**，写了静默失效。

### private/*.yaml —— ⚠️ 不在 AI 整理范围
产品型号参数、服务承诺、完工案例**必须真实**，由你自己按模板填——
AI 编一个案例写进脚本就是事故。规范同上：带 `source` 与 `verified` 日期、留空走占位符。

## 三、给任何 AI 的整理指令（复制这段，填两处空，连资料一起发）

```text
你是一名【____填行业名____】短视频内容知识库编辑。请把我提供的资料整理成"口播脚本知识库"，
严格按以下格式输出，供导入脚本生成工具。

【业务描述】____填一句话____

━━━ 总规则 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 只依据我提供的资料与你可靠的行业常识撰写；标准编号、法规文号、具体金额/数据
   一律不得编造——不确定的归入"待核实清单"
2. 能用数字的绝不写形容词；禁止绝对化用语（最/第一/绝对/100%/永不/官方补贴类）
3. 每个细分领域必须配"常见误区"表；误区的"事实"列要具体到可讲成一段口播
4. 输出 = 多个代码块，每个代码块前单独一行标注【文件名】；除此之外不要任何解释

━━━ 输出一：【knowledge/topics.md】━━━━━━━━━━━━━━━━
先给出 5~8 个细分领域名（短词，如"板材环保/预算报价"）。
然后每个细分领域一章，格式严格如下：

## 1. 细分领域名
### 核心知识点
- 3~6 条，优先带数字、对比、流程
### 常见误区
| 误区 | 事实 |
|---|---|
（≥2 行）
### 需占位的事实
该领域必须由商家提供的数据/政策，一行一个

━━━ 输出二：【knowledge/audience.md】━━━━━━━━━━━━━━
3~5 类受众，每类一章：
## 1. 受众名
### 深层恐惧（痛点）
、4~6 个顿号短语
### 高频疑问（选题金矿）
- 8~10 条真实会问的问题
### 推荐CTA
一句话

━━━ 输出三：【knowledge/ideas.md】━━━━━━━━━━━━━━━━━
≥30 条编号选题，**每行形如 `编号. 标题 — 钩子类型`**（钩子类型只能取
`patterns/hooks.md` 钩子库里的 10 类；这一节会被注入选题阶段的提示词，
钩子类型是模型读 `hook_type` 的唯一来源，省了它模型就会自己编）。
覆盖全部细分领域与受众。

━━━ 输出四：【compliance-industry】━━━━━━━━━━━━━━━━
本行业特有红线 5~8 条（广告法之外的），每条一句可执行禁令。

━━━ 输出五：【banwords-extra】━━━━━━━━━━━━━━━━━━━━
extra_hard:（行业特有、出现即违规的词）
（extra_soft 已废弃：引擎不读，写了静默失效，不要产出）

━━━ 输出六：【verify-list】━━━━━━━━━━━━━━━━━━━━━━━━
需人工核实的标准/法规/政策名称清单（只写名称，绝不写编号）。

━━━ 我的资料如下 ━━━━━━━━━━━━━━━━━━━━━━━━━━
（粘贴资料；没有资料就说"无资料，基于行业常识"）
```

## 四、把 AI 产出导入行业包（五步）

1. **铺结构**：复制 `packs/elevator/` → 改名为你的行业（如 `packs/decoration/`）
2. **放内容**：AI 输出的各代码块**覆盖**新包里同名文件
   （topics.md / audience.md / ideas.md；industry 红线写入 `compliance/industry.md`）
3. **改清单**：编辑 `pack.yaml`——`name`/`display_name`/`description`、
   `params.segment.options`（= topics 章节名）、`audience.options`（= audience 章节名）、
   `topics_map` / `audience_map`（同名映射）、`draft: true`
4. **并词表**：把 `banwords-extra` 追加进 `banwords.yaml` 的 `hard:` / `soft:` 列表
5. **验证**：刷新界面选中新包 → 生成一条试效果；把《待核实清单》逐项核实后补进 `knowledge/standards.md`

> 私有资料（型号/案例/承诺）不经过 AI——用 `private/` 模板自己填，留空的自动走占位符。

## 五、质量自检（导入后 2 分钟过一遍）

- [ ] 选每个细分领域生成一次，无"正确的废话"（说明知识点足够具体）
- [ ] 误区表条目能在生成结果里变成反常识钩子
- [ ] 待核实清单已处理或已有占位提醒
- [ ] 禁用词校验通过（生成一次看「合规」页签：硬禁用 0）
- [ ] `pack.yaml` 的 `topics_map` / `audience_map` 与章节标题逐字一致
