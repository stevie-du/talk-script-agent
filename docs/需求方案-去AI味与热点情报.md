## 第一部分 · 对标：别人到底怎么算的

### 1.1 去AI味（文案质量）

| 对象 | 类型 | 核心逻辑 / 算法 | 特殊差异点 |
|---|---|---|---|
| **Wikipedia: Signs of AI writing** | 社区规范 | 人工长期维护的"AI 痕迹"目录，每条**有名字、有真实例句**，可逐条比对 | 它是几乎所有 humanizer skill 的上游词源；被反用（拿它当"藏 AI"手册）后价值转向"命名"而非"检测" |
| **op7418/humanizer-zh** | 开源 skill | 24 条模式分 5 类（内容/语言语法/风格/交流/填充）+ 6 条快速检查清单 + **5 维 ×10=50 分**评分表 | 中文语境化：把"三段式法则""否定排比""刻意换词""虚假范围"落成中文可扫条目 |
| **hardikpandya/stop-slop** | 开源 skill | 同上 5 维评分，**明确写死门槛：<35/50 就 revise** | 把"评分"和"是否重做"绑成一个可执行规则，而不是给人看的参考分 |
| **blader/humanizer** | 开源 skill | 25 条 tell **按强度与频率编号**；强 tell 单次命中即改，弱 tell 需多处命中才改 | **severity 分级 + 命中阈值挂钩** —— 这是最该抄的机制，直接对应我们 strong/weak |
| **conorbronsdon/avoid-ai-writing** | 开源 skill | **74 个模式类 + 112 条词替换表**；命中按 **P0/P1/P2** 分组；`detect` 与 `rewrite` 两态；**最多 2 遍编辑，且"纯检查不消耗编辑次数"** | 把"回炉预算"当成稀缺资源管理 —— 对应我们 `recheck_rounds`，别把文风轮次和合规轮次混抢 |
| **MrGeDiao/shuorenhua** | 开源 skill | **三档改写范围** structural（可删重排）/ bounded（只句内）/ in-place（不删句）；**123 条评测集**，通过线 = 正常文本误改率 <10% 且 7 条正向样本 ≥5 条有收益 | 唯一把"**误伤率**"当硬指标的项目；我们只有一句"别矫枉过正"的告诫文字 |
| **Anyword** | 商业 | Predictive Performance Score = **预测转化率**，用 7 年、数百万条营销素材做训练；每个变体单独打分；额外输出受众年龄/性别分布与"主情绪驱动" | **它的分不是"像不像人"，是"有没有效果"** —— 和 style 分是两根轴。多稿并排各打一分是其核心交互 |
| **降AI率工具群**（秘塔/笔灵/before-ai 等） | 商业 | 检测端 = 困惑度 + 突发度 + 分句窗口 + 分类器；改写端 = 同义词替换 / 句式重组 / 语义层打散，承诺"降幅 <20% 退款" | 副作用被自己承认：**伤流畅度**。这是"以检测器为目标函数"的必然结果 |
| **腾讯朱雀**（matrix.tencent.com/ai-detect） | 商业/免费 | 国内创作者事实上的检测标准；创作侧已有"逆向朱雀"提示词产业链，平台侧大概率用朱雀系 | **不做门槛**（滕王阁序被判 100% AI 是现成误判反例，维持 §学术侧结论）；只做 **A4 校准的外部锚点**——人工抽产物+真人稿对照 L1 分数相关性，相关性差 = tell 集盲区（§2.10 A-7） |
| **学术侧** | 论文 | ① few-shot 比 zero-shot 风格匹配高 **23.5 倍**，completion（给真人稿续写）**99.9%** 与原作者一致；② **风格保真与可检测性可分离**（人困惑度 29.5 vs LLM 15.2）；③ Pangram：困惑度/突发度会把**公有领域文本与非母语写作者误判为 AI** | ①说明**样本 > 清单**；②③说明**统计量不能当门槛**，只能当诊断 |
| **宝玉（实践派）** | 文章 | "提示词是死的，Skill 是活的"：从**你自己的原创文本**提炼规则 → 人工修订模型产出 → diff 回写规则，循环进化 | 通用清单会造成**新的雷同**；风格必须是个体化的 |

**归纳出六条可执行机制**（不是理念）：
1. **tell 要可命名、可定位、可计数**（Wikipedia/humanizer 系）
2. **severity 分强/弱，且弱必须累计多处才报**（blader）
3. **评分与门槛分离**：先只报分跑分布，再定线（stop-slop 有线，shuorenhua 有回归集）
4. **改写要分范围 + 有"误改率"回归集**（shuorenhua）
5. **风格靠样本迁移，不靠清单**（23.5× / 99.9% / 宝玉）
6. **效果分与风格分是两根轴**（Anyword）→ 我们有别人没有的资产：**用户自己账号的真实表现数据**

## 第二部分 · 补全后的方案

### 2.1 去AI味：三层评分，不是一层

```
L1 规则命中分（确定性，可解释）      ← 抄 blader 的 severity + avoid-ai-writing 的分级
L2 形态统计分（诊断，永不参与门槛）  ← 突发度/变异系数/n-gram 重复；Pangram 证明它误伤
L3 表现分（可选，来自用户回填）      ← Anyword 那根轴，我们有独家数据源
```

**L1 tell 集（10 条，默认关：yaml 不声明就不跑）**

| id | 中文名 | 算法 | severity |
|---|---|---|---|
| `parallel_triple` | 排比三连 | 同段内「、」连接 ≥3 项且字数极差 ≤3 | weak（采 `packs/elevator/ai_tells.yaml:19`，A-4③：结构类里它最像自然列举） |
| `list_enumeration` | 清单体 | 连续 **≥4** 句以"第一/第二/…"**递增**开头（孤立"第一件事"不算）；也认"一是/二是/三是"形态（2026-09-23 补入 spec，§2.10 A-6 #4：spec 漏记，实现没错）。⚠ 阈值 3→4 是 A-4 决策预实验定的（`0864e73`）：≥3 把「正确做法就三步」这类正当分步讲解 94 段误判成清单体，≥4 后误伤清零 | weak |
| `uniform_para_len` | 段长等长 | ≥3 个 point 段，字数变异系数 <0.15 | weak |
| `repeat_opening` | 句首重复 | 同一二字开头占句数 >1/3 且 ≥3 句 | weak |
| `no_specific` | 通篇零具体 | 无阿拉伯数字、无"数词+量词"、且无 `{{待补}}` | **strong** |
| `bookish_connective` | 书面连接词 | 词表不重叠扫描（长词优先） | weak |
| `abstract_noun_ending` | 抽象名词收尾 | 句末匹配词表 | weak |
| `slogan_closing` | 口号式收尾 | cta 段命中词表且无第二人称/疑问句 | **strong** |
| `opening_ban` | 开场禁区 | 首句以词表开头 | **strong** |
| `filler_stack` | 填充词堆叠 | 同一段里填充词命中总数 ≥2（**可跨词**：「其实×1 + 真的×1」也报）——原 spec 写"同一填充词 >1 次"，2026-09-23 按实现改 spec（§2.10 A-6 #3：跨词累计更符合"堆词"本义） | weak |

- **词表在 `packs/<行业>/ai_tells.yaml`，代码里零行业词**（多类目前提）
- 弱 tell 阈值分两族（落码口径，`ai_tells.py:216`）：**词表类**单段命中总数 ≥2 才报（`WEAK_MIN=2`）；**结构类**走各自阈值（≥3 项 / 递增 **≥4** 句 / cv<0.15 / 句首 ≥3 句且 >1/3）。未达阈值的类**不显示为命中**
- 分数：`100 − (strong 命中**条**数 ×12 + weak 命中**条**数 ×4)`，**初值，待 A4 校准**（按条计不按处计——一条并列串、一段词表命中各算一条；每条 hit 带 `count` 处数与 `where` 定位，`ai_tells.py:267-270`）
- **不进 `passed`**（`checker.py:466` 硬编码只报不拦，`tells=None` 时字段落 null——「没测」与「测了很好」是两种形状；spec 原句"由配置决定"的开关未实现，见 §2.10 A-6）

**L2 只诊断不拦**：句长变异系数、n-gram 重复率、罕见词比例。界面显示为"形态指标"，注明"参考，不作判定依据"。

**L3 表现分**：结果页加一行"这条发出去表现如何"（播放/完播/涨粉），攒够 N 条后按 `segment × style × hook_type` 出胜率 —— 这是唯一无法被外部产品复制的资产。

**改写范围三档**（抄 shuorenhua，解决"矫枉过正"）：
`in-place`（只句内清理，不动事实/`{{待补}}`/cta 动作）→ `bounded` → `structural`。默认 `bounded`。

**误改率回归集**：20–30 条"人味本来就正常"的稿子做固定回归，任何词表改动必须 **误报 <10%** 才能合入。

### 2.2 热点情报：三信号 + 增长率 + 源注册表

**合成公式（摊开显示，不给黑箱总分）**

```
需求 D = 0.6·搜索增长 + 0.4·需求词新收录
  搜索增长 = (近7天均值 − 前28天基线) / 基线      ← Exploding Topics 的增长形态思路
  新收录   = 本次下拉词集合 − 上次集合（新增即 +1）
供给 S = log(1 + 近30天同类新增条数) / log(1 + 总条数)   ← 越大越红海
机会分 = D × (1 − S)                                   ← 蝉妈妈"高互动低竞争"的可计算版
事件 E = exp(−Δ天 / τ)，τ 按类型：事故 3 / 政策 30 / 季节话题 90
季节性剔除：同一词在去年同期有峰值 → E 打折（抄 ET 的 seasonality）
波动率惩罚：D 方差过高（单点尖峰）→ 标"疑似昙花一现"，需人工确认
```

**源注册表（多类目关键）**：`pack.yaml` 新增 `intel_sources`，每个源声明**自己在界面上的名字**；
引擎按声明跑，**渲染层一个平台名都不写死**。新行业包由 packgen 生成初版配置。

```yaml
intel_sources:
  - id: demand_terms        # 引擎侧适配器名（代码里按 id 找实现）
    label: 下拉词           # 界面上显示什么
    platform: 百度/必应     # 组标题第二半 + 情报源页那一列
    role: 雷达              # 分区标题里的「· 角色」
    cadence: daily          # 抓取节奏：daily / weekly / monthly / quarterly / on_demand
    note: 搜索联想词 diff，比政策文件滞后出现   # 分区标题后那句 hint，可省
  - id: bilibili_search
    label: B站同类
    platform: B站
    role: 供给度量
    cadence: on_demand
  - id: hot_board
    label: 抖音热榜         # 同一个 hot_board 适配器，按 platform 参数出多个源
    platform: 抖音
    role: 破圈触发器
    cadence: daily
    params: { board: douyin, match: keyword }
  - id: xhs_board
    label: 小红书
    platform: 小红书
    role: 破圈触发器
    cadence: "—"
    enabled: false          # 声明了但没接：不进筛选行/分区，只在情报源页说明为什么
    note: 没有可用公开榜，要 x-s 签名逆向 —— 不做
```

**落点（已查实的接缝，不需要新机制）**：
`app/schemas.py:181 PackInfo` 加一个 `intel_sources: list[IntelSource] = []` 字段 →
`app/knowledge.py pack_info()` 里 `data.get("intel_sources", [])`（与 `topics_map`/`audience_map`
同一读法）→ `/api/meta` 的 `packs[]` 已经 `model_dump()` 全量下发（`app/server.py:707`），
**前端不用新接口就能拿到**。校验挂在现成的 `param_audit` 上：未知 `id`（引擎里没有这个适配器）
记一条 note 而不是报错 —— 与"用户能选但本包没定制"的降级口径一致。
`enabled: false` 的源照常下发，界面据此显示「未接入 N」与原因。

**这条配置同时决定四处**（一处声明，四处一致，不会漂）：
① 选题页的**分区**（`label · role` + 组内卡片）；② 筛选行的 chip 与计数（只列 `enabled` 且有货/接了的）；
③ 左栏 nav 的计数；④ 情报源页那张表（`id / role / cadence / 接入 / 上次 / 命中`）。
证据：`_verify/_proto-1to1.html` 里电梯与门窗定制两个包用**同一套渲染代码**，
只换 `PACKS` 里那份配置 —— 分区、chip、计数、「未接入 N」全跟着变（图 `_1to1_topics.png` / `_1to1_doors.png`）。


**工程约束（已定）**
- 抓取器在生成主链路之外；懒触发（打开选题页时按"上次抓取距今"补跑），**走 Job 管道 + 独立并发额度**
- 落点在 `data_dir/intel/<pack>/`；不进安装包
- 去重按 `guid > url` 优先级 + 每话题上限（TrendRadar）
- **AI 归并失败 → 回落关键词/`topics_map` 匹配**（TrendRadar 的兜底路径），保证无 Key 也能出原始条目列表
- 聚类：条数 <50 用 LLM 批量归并；>50 才考虑 c-TF-IDF 式轻量聚类，**不引入 BERTopic 重依赖**
- **intel 只进 `select`，不进 `write`**：政策原文含"政府补贴"这类 banwords hard 词，进正文层会让模型照抄后被判违规、陷入回炉死循环

### 2.3 我们的差异化（相对上面所有对标）

1. **口播细分**：同行做"文章去AI味"，没人做"念出来不拗口"——我们有 TTS+ASR 回读这条独有验证路径
2. **本地私有**：语料、回填数据、词表都在用户机器上，不上传
3. **合规联动**：ai_tells 与 banwords 同一套扫描器与对账测试，不造第二套规则引擎
4. **口径可引**：政策原文带文号进 prompt，同时治"AI 味"和"编事实"
5. **降级完备**：无网络 / 无 Key / 无数据三种情况都有明确退路

### 2.9 复核后的优化清单（2026-09-22，逐条带证据）

A 线已经落进代码，所以这一节不是"再设计一遍"，而是**拿成熟做法回头照我们的实现**。
每条都标了成本；标「已核实·不是问题」的不要再当待办去"顺手优化"。

#### A 线

**A-1 满分通道：全是 `{{待补}}` 的稿子拿 100 分、零命中。** 实测三份稿件跑 `AITells.report()`：
正常稿 100 / **全是待补 100（零命中）** / 空话稿 88（报 `no_specific`）。
根因是 `ai_tells.py:195` 的豁免 —— 只要全文出现任意一个 `{{…}}`，"通篇零具体"这条**最致命**的
tell 直接不判。而 `checker` 的 report 里**根本没有占位数字段**（只有 `chars_total` / `segments` / `points`），
所以"整篇没写、只留了一排空"这件事在整条链路上是隐形的。
豁免本身是对的（占位比编数字诚实），错在**没有边界**。
改法：① report 加 `placeholders: {count, per_100}`；② 豁免加上限 —— 占位数 ≤ 段数才豁免，
超过就是"没写"而不是"留了个空"。成本：小（一个计数 + 一个条件），**建议本轮就做**。
**2026-09-22 二轮复核：仍未落码**，实测复现——8 段全 `{{待补}}` →
`score:100, hits:[]`，report 无 `placeholders` 字段（keys 仅 config_warnings/hits/score/strong/tells_enabled/weak）。

**A-2 三档改写范围不用新做 —— 语义已经在代码里。** `pipeline.py:860-862` 的回炉反馈尾巴已经写着
「不要另起一炉重写、不要改动了未点名的段落」，这正是 shuorenhua 的 `bounded` 档。
改法：把这句话升格成显式参数 `rewrite_scope`（默认 bounded），`in-place` 只多一句"不删句、只换词"，
`structural` 才允许重排。成本从"改 prompt 结构"降到"一个参数 + 两句文案"。

**A-3 误改率回归集与 A4 校准共用同一批产物。** 一份夹具两用（省一半工时），
但**必须按 `result.mock` 分流** —— 历史产物 86/87 是 mock，夹具里自带"第一/第二/第三"清单体，
不分流则回归必挂（这条踩过）。合入门槛：正常稿误报 <10%。成本：纯测试资产，不动模型、不加耗时。
**2026-09-22 增补（tenten 对抗测试法）**：夹具还要放**绝不能改的负样本**——政策原文、法条、
数字密集句、引文。`in-place` 档的合格线就是"一条都没动"，这比"人味正常稿"更能钉住改写范围三档的边界。

**A-4 三处代码/方案不一致，建议改文档而不是改代码。**
① 扣分按"条"不按"处"（`score_of` 对每个 hit 扣一次，`count` 只进详情）——
按条计其实**更稳**：一段里连 3 处排比是"一条改法建议"，不是三条，回炉提示不该被数量绑架；
② `WEAK_MIN` 只管词表类，结构类走各自阈值（≥3 项 / ≥3 句 / cv<0.15）—— 这是对的，
但我原型里"句首重复 ×1 未达阈值不报"是**编错的说法**，已作废；
③ 排比三连在 `packs/elevator/ai_tells.yaml` 是 weak，我那张表定 strong —— 采 yaml（结构类里它最像自然列举）。
文档 §2.1 的公式措辞相应改成「按命中条数扣分，每条带处数」。

### 2.11 本轮落码的实测结果（2026-09-23）

这一节只记**做的时候才知道的事** —— 规格里没写、实测才暴露的。规格本身不再复述。

#### A-3 误改率回归集：第一次跑就把门槛踩破了

按 §2.1 定的「正常稿误报 < 10%」建了 23 篇语料，第一次实测是 **39.1%（9/23）**。
两个元凶，性质完全不同：

| 元凶 | 命中 | 性质 | 处置 |
|---|---|---|---|
| `parallel_triple` | 6 篇 | **真缺陷**：md 的依据写的是「排比三连**占满一段**」，实现却是"段里出现一处 ≥3 项并列就报" | 补 `PARALLEL_COVERAGE`：并列串要吃掉该段一半以上的字 |
| `no_specific` | 4 篇 | **两份依据不一致**：§2.1 按"有没有数字"判、`anti-ai-smell.md` 按"有没有数字/**场景**"判 | 口径未定，单列 `BORDERLINE` 族"钉住现状"，**不混进 <10% 的分母** |

否则很容易把"分母怎么切"当成调参手段 —— `BORDERLINE` 单列一族就是为了这个。

#### 对账表放错了地方（差点把提示词撑爆）

A3 原计划把可解析的对照表放进 `patterns/anti-ai-smell.md`。实测撞两条门禁：
它是**整份注入提示词**的，而撰写一轮的用户提示词预算 < 7600 字、当时只剩 **28 字余量**；
而且渲染出来的提示词里不许出现 `*.md` / `*.yaml` 路径（`test_dangling_refs`）。
改成用**不进提示词**的本文 §2.1 作第三方依据。规律：`anti-ai-smell.md` 是
**给模型看的清单**，不是给 CI 看的账本。

#### 还有两处 spec 与实现不一致（§2.10 那张表之外）

- `abstract_noun_ending`：spec 写"句末匹配词表"，实现是全文扫描。**改 spec 认实现**
  （与 A-6#3 同类：弱 tell、单段 ≥2 处才报，误伤代价低）。tell 名里的 "ending"
  是历史命名，不代表实现只在句末判。

  **没有对应 tell** —— 引擎不会报它们。已在 md 的散文里保留为"人工检查项"，
  但**不能放进注入段**（预算只有 28 字），所以这条欠账记在这里而不是那里。

#### B 线首版公式（B-1）落成了什么

```
D（需求，相对值）= 该细分领域本次「新收录」条目数 ÷ 本次各领域里最大的那个
S（供给，相对值）= 该细分领域 B站同题条数     ÷ 本次各领域里最大的那个
E（事件）        = exp(−Δ天 / τ)，τ 按来源角色（热榜 3 / 雷达 14 / 口径库 30）
机会分           = D × (1 − S)
```

⚠ **D/S 是"细分领域"粒度、不是"单条"粒度**，这是刻意的：单条需求词的"新收录"
只有 0/1 两态，硬做成 0..1 是**假精度**（界面上的 0.92 会让人以为有个它其实没有的刻度）。
单条粒度等 A4 校准之后再说。

「算不出」与「0」严格分开：D 或 S 缺数据 → 机会分 `null` → 界面显示「—」。
0 的意思是"竞争激烈、没机会"，与"我们没测"结论相反。

#### B-2 落成了"零模型调用"

`app/intel.py` 里**没有一次模型调用** —— 归并是确定性的（`topics_map` + segment 选项）。
所以"没配 Key"对今日选题**完全无影响**：首装用户打开选题页看到的是一页真实条目，
不是空白、也不是"请先配置模型"。有一条测试把 `Pipeline.llm` 打成必炸来钉住这一点。

#### B4 的两族并发额度：为什么必须拆

抓取是**纯 HTTP、不花模型的钱**。塞进 `MAX_CONCURRENT_JOBS` 的后果是"点一次重抓"
把生成的名额占掉，用户看到「生成已达上限」而占着名额的是一个不花钱的请求。
所以：`INTEL_BUSY_STATES` + `MAX_CONCURRENT_INTEL`，两族各数各的；
前端「在跑」的判据改比 `ALL_BUSY_STATES`（两族并集）—— 它只关心"这条还在动吗"。
断言直接钉住"情报额度占满时生成照样能开起来"（只测 `running_count()==0` 测不出这个）。

#### UI 侧抓到并修掉的三个真 bug（都由新断言抓出来）

1. 分区桶按 `x.label` 找、而桶里存的是 `x.g` → **每张卡各成一组**，组标题重复，
   "一个来源一组"静默失效。判据：组数必须**严格小于**本页卡片数。
2. 情报源表的 `last` 变量写了却没进模板 → **表体比表头少一列**，数据行整体左移，
   而表头看着完全正常。判据：表体列数 == 表头列数。
3. 「未接入 N」chip 整段被变异工具删掉后没还原（工具自身的缺陷，见下）。

#### 变异检验工具的两次自身缺陷（值得记）

- **`_verify/mutate.py` 的还原是"写回内存里的原内容"**，所以一旦进程被杀
  （SIGTERM），残留会留在工作区；下一次运行把残留当"原始内容"备份 →
  **残留被永久保留**。实测：`topics.js` 里被追加了三份
  `import('./jobs.js').then(m => m.send())`，而每条变异都报"报红 OK"（红的是残留）。
  修法：改文件前先落崩溃恢复日志、还原成功才清空；启动时发现日志还在就按它还原。
  （清空而不是删除 —— 沙箱会把删除工作区文件拦下，工具自己成了阻塞项。）
- **选择器用 `split()` 会把 `-k 'a or b'` 拆成三个参数**，pytest 报用法错误 →
  退出码非零 → 被读成"报红 OK"。改用 `shlex`，并显式区分"没收集到用例"（退出码 5）
  与真报红；界面断言那一侧还要区分"整网崩了"与"断言红了"。

#### 结果页三样（§2.7）的口径

- **每段语速**：`字数 ÷ 净口播秒数`。⚠ 时间轴把**段间停顿算在段里**
  （`pipeline._compute_timings`），必须减掉 —— 不减的话每段都被读成偏慢，
  而那是系统性偏差、不是某一段的问题。
- **人味标记回到正文**：只加下划线、**不改文字色**（拿 `--warn` 当正文色就撞上
  §2.6 那笔对比度欠账）。为此给 `TellHit` 加了 `words`（命中处的**原文片段**）——
  不让渲染层去解析 `detail` 展示串，改一个标点就会让解析静默失效。

#### B7 落地的实测记录（2026-09-23，`f418e79`）

- **只进 select 是错的（见 B-3'）**：两个目标包都是合并 `draft` 路径，
  `select` 模板从不被调用。只按待确认 #7 原话接 select，情报**实际进不了任何提示词**
  却看起来"做了"。改 draft_ctx 同样注入后，用 `test_intel_b7.py` 的**反向断言**
  （"每个带 select/draft 的包模板必须引用 `$intel_block`"）钉死 —— 正向断言
  （"ctx 该提供的都有"）抓不住"模板忘了引用"这类接线断。
- **⚠ 模板注释里不能写 `$xxx` 令牌字面量**：`_placeholder_audit` / `unfilled()`
  全文扫模板，注释里写 `$feedback_block`（即使只是"与它同一条规矩"的解释）会被
  误判成"引擎不提供的占位符" → 两条既有测试报红。注释里只写变量名不带 `$`。
- **排序键**：本领域 > 通用 > 别的领域；有出处优先；机会分/新鲜度兜底 ——
  与 `_prompt_rank` 一致。被 hard 禁用词摘掉的条目**返回给调用方记作业日志**
  （`intel_drop` step），否则"摘了"无人知晓。

#### A-4 决策预实验：两个调法都让尺子"永不响"（2026-09-23 17:00 复量）
