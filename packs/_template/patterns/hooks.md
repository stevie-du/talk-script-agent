# 开场钩子库与风格模板（模板包 · 行业中立骨架）

> 本文件会被**原样复制**进每个新生成的行业包，所以里面的实例一律与行业无关。
> 建包后请把「实例」列换成你行业的真实说法（**钩子句里不要出现无法核实的资历与数字**：
> 从业十几年、七万三千次、九成的人都…这类自证既过不了广告法，也不是好钩子）。

## 一、钩子库（前 3 秒定生死）

按类型选用，**同一主题跑多版时应换不同类型**，避免 5 版一个样。
`hook_type` 只能取下面这 10 类里的名字（选题阶段的输出契约按这个取值域校验）。

| 类型 | 结构 | 实例（建包后换成本行业的说法） |
|---|---|---|
| 反常识 | 打破一个你以为是常识的认知 | `这个东西真的不会坏吗？答案跟很多人想的不一样。` |
| 场景代入 | 描述受众经历过的具体场景 | `你正忙着，它突然不动了——这一刻你该怎么办？` |
| 悬念提问 | 抛问题，答案压后 | `出问题时第一件事该做什么？很多人的第一反应是错的。` |
| 损失厌恶 | 指出一个正在发生的风险 | `你家那张贴纸上的日期，过没过，你注意过吗？` |
| 身份背书 | 用从业者身份建立信任（**不写年限与台量**） | `我就是干这行的，今天说说我们内部人自己怎么做。` |
| 数据冲击 | 用具体数字开场（数字必须来自私有资料/可核实来源，缺就写 {{待补：数字}}） | `它一年要跑多少趟？这个数比你想的大得多。` |
| 对比反差 | 前后 / 新旧 / 正反对比 | `同样两件东西，一件用得久，一件老出毛病，差在这一件事。` |
| 直接痛点 | 一句话戳中 | `要办成这件事，卡的多半是这一步。` |
| 故事开场 | 短场景叙事（不编具体人名地名，缺就占位） | `有个客户找上门，原因特别简单。` |
| 误解纠正 | 点名一个流传很广的错误说法 | `很多人说这样做更安全，这个说法害人不浅。` |

### 钩子禁用清单

- ❌ `大家好，我是……`（自我介绍放在钩子后面或干脆不放）
- ❌ `今天给大家讲讲……` / `今天来聊聊……`
- ❌ `你知道吗？`（过度使用，已无吸引力）
- ❌ `随着……的发展`（书面语开场）
- ❌ 长铺垫、背景介绍、寒暄
- ❌ 无法核实的资历与概率自证（干了十几年 / 服务过 X 万台 / 九成的人…）
- ❌ 法律定性与恐吓式开场（"还在用就是违法""等着被罚款"）——口径见本提示词的【行业红线】段

### 钩子与平台匹配

| 平台 | 推荐钩子类型 |
|---|---|
| 抖音 | 反常识、悬念提问、直接痛点（强度最高） |
| 小红书 | 场景代入、故事开场、身份背书 |
| 视频号 | 身份背书、场景代入、误解纠正（避免惊悚） |
| B站 | 反常识、悬念提问（可学术化） |

## 二、风格语气模板

> 章节名与 `pack.yaml` 的 `style` 选项**必须一致**（引擎按风格只注入这一套；
> 名字对不上会退回整份文件，白多带几套别的语气）。

### 权威科普
- **语气**：平实、准确、有分寸，不煽情
- **句式**：陈述句为主，适当用短句强调
- **用词**：规范术语，必要时立刻口语化解释（`某某装置，简单说就是……`）
- **避免**：夸张修辞、感叹号、绝对判断
- **适用**：政策解读、标准科普、技术解析、B站/视频号

### 亲和接地气
- **语气**：像身边懂行的人聊天
- **句式**：短句、口语词（"其实""说白了""你就记住"）、适当反问
- **用词**：术语后必须跟一句大白话
- **避免**：书面语连接词（因此、由此可见、综上所述）
- **适用**：面向普通用户的常识科普

### 幽默玩梗
- **语气**：轻松、自嘲、有梗
- **句式**：夸张对比、反转
- **用词**：网络语适度，不过时不过量
- **避免**：拿安全事故/疾病/损失开玩笑、拿特定人群开玩笑、低俗梗
- **红线**：**涉及人身安全与伤亡的话题一律不得用幽默风格**

### 严肃警示
- **语气**：郑重、有分量、节奏慢
- **句式**：短句、停顿多、重复关键动作
- **用词**：准确、不加修饰
- **适用**：违规操作警示、事故预防、监管要求
- **注意**：警示不等于恐吓，要给明确可行的正确做法

### 销售转化
- **语气**：热情但不油腻，专业且可信
- **结构**：痛点 → 后果 → 方案 → 证据 → 行动
- **用词**：具体（数据、年限、响应时长）优于形容词；**数值必须来自私有资料，缺就写 {{待补：xxx}}，绝不虚构**
- **避免**：极限词、逼单话术、虚假承诺（引擎会按本包的禁用词表校验，命中就打回改写）
- **关键**：**每提一个卖点，必须配一个证据**（案例、数据、资质）

## 三、风格与受众交叉建议

> 建包后按 `pack.yaml` 的实际受众改写本表；受众名与选项不一致时这一段只是参考。

| 受众 | 推荐风格 | 说明 |
|---|---|---|
| 普通用户 / 终端消费者 | 亲和接地气 / 严肃警示 | 懂行少，怕专业词 |
| 采购与管理人员 | 权威科普 | 关心责任边界和合规 |
| 同行 / 专业受众 | 权威科普 | 术语可直接用 |
| 企业客户 / 渠道 | 权威科普 / 销售转化 | 关心成本、周期、验收 |

## 四、口语化硬性检查

生成后逐句检查：

1. 单句超过 25 字 → 拆开
2. 出现"因此""由此可见""综上所述""值得注意的是" → 删掉
3. 出现"进行XX""实现XX""提供XX保障"这类书面动宾 → 改成口语动词
4. 连续三句以上长度相同 → 打断节奏
5. 有可以删掉还不影响意思的词 → 删掉

**检验方法：念出来。** 念着别扭的地方，观众听着也别扭。
