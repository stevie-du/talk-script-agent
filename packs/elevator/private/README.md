# 私有资料目录（L2 · 你的差异化壁垒）

这个目录放**只有你有的东西**：产品型号参数、服务承诺、完工案例、客户异议应答。
它是脚本从"正确的废话"变成"能卖货的内容"的关键。

> **重要**：本目录与规则文件分离。你把 Skill 分享给同事时，只分享上级目录的其他文件，
> 不含 `private/`，商业信息不外泄。

---

## 这是持久化的底层知识库

**资料写进这里一次，之后每次生成脚本自动读取，你不需要重复提供。**
对话只是"录入"这一步——录完就结束，不是每次的前置动作。

## 三种方式给我资料（任选，可混用）

### 方式一：丢文件（资料多时首选）
**资料多**：直接放进 `private/raw/` 目录，说一句 `处理一下 raw 里的资料`
**资料少**：直接丢进对话，说 `整理进 private/products.yaml`

PDF / Word / Excel / 图片都行。我会读完后抽成结构化条目，你核对一遍即可。
原始文件保留在 `raw/` 备查，日后更新只需替换文件再处理一次。详见 `raw/README.md`。
> `把这份资料整理进 private/products.yaml`

我会读完后抽成结构化条目，你核对一遍即可。**推荐用于手册类厚资料。**

### 方式二：对话里直接贴（最快）
零散参数直接打字发给我：
> `记住：我们主力机型 XXXX，载重 1050kg，速度 1.75m/s，无机房，永磁同步`

我会当场写进对应文件。**推荐用于临时补充和纠错。**

### 方式三：自己照模板填（最规范）
直接编辑本目录下的 yaml 文件，按注释填写。**推荐用于长期维护。**

---

## 填写原则（决定好不好用）

1. **能数字化的绝不写形容词**
   ❌ `响应速度快`　✅ `市区 2 小时内到场`
   模型拿"快"写不出有说服力的句子，拿"2 小时"可以。

2. **参数必须带单位**
   ❌ `载重 1050`　✅ `1050 kg`

3. **每条带来源和日期**
   `source: 2026版产品手册` / `verified: 2026-09-06`
   标准参数和型号会换代，没日期的条目迟早变成错误内容。

4. **宁缺毋滥，不确定的留空**
   空着我会用占位符 `{{待补：xxx}}` 提醒你，不会瞎编。
   **填一个错的值，比空着危险十倍。**

5. **只填常用的**
   全部型号塞进来会稀释重点。先填主力机型 3~5 个。

---

## 填写优先级

| 优先级 | 内容 | 为什么 |
|---|---|---|
| **P0** | 主力型号参数（3~5 个） | 产品推介脚本的硬素材 |
| **P1** | 服务承诺（响应时长、质保、覆盖范围） | 信任建立的核心，比形容词有效 |
| **P2** | 完工案例（5~10 个） | 转化率最高的素材 |
| **P3** | 客户异议应答 | 评论区转化用 |

---

## 不要放什么

| 不放 | 原因 |
|---|---|
| 报价底价、成本价 | 一旦写进知识库，模型可能直接写进脚本 |
| 客户名单、联系人、电话 | 隐私与商业风险 |
| 竞品内部资料 | 法律风险 |
| 未公开的项目信息 | 保密要求 |

**报价的正确处理方式**：不写具体数字，写逻辑和区间规则。
✅ `总价由设备价、安装、土建、管线迁改四部分构成，土建和管线占比常超预期`
❌ `最低 38 万`

## 文件说明

| 文件 | 放什么 |
|---|---|
| `products.yaml` | 产品型号与参数 |
| `service.yaml` | 服务承诺、响应时效、覆盖范围 |
| `cases.yaml` | 完工案例 |
| `faq.yaml` | 客户常见异议与标准应答 |

## 维护

参数换代、服务政策调整后，更新对应条目并改 `verified` 日期。
建议**每季度过一遍**，过期信息比没有信息更伤专业度。
