# 私有资料目录（L2 · 你的差异化壁垒）

这个目录放**只有你有的东西**：产品型号参数、服务承诺、完工案例、客户异议应答。
它是脚本从"正确的废话"变成"能卖货的内容"的关键。

> **重要**：本目录与规则文件分离。你把 Skill 分享给同事时，只分享上级目录的其他文件，
> 不含 `private/`，商业信息不外泄。

---

## 这是持久化的底层知识库

**资料写进这里一次，之后每次生成脚本自动读取，你不需要重复提供。**
写入这个目录是**编辑文件**这个动作 —— 应用不会替你把对话里发的内容存进 yaml。

## 三条把资料变成 yaml 的路（任选，可混用）

### 路一：先保管原件，再手工整理

原始文件放进 `private/raw/`（**引擎不读这个目录，也不会自动解析**，它只是备查）。
要生效必须落到上层的 yaml，见路三。详见 `raw/README.md`。

### 路二：临时补充 —— 走输入区的「补充资料」

生成时不想改文件，可以把要点贴进输入区的「补充资料」框。
**它只对本次生成有效**，不会写进 `private/`，下次生成得再贴一次 —— 长久之计还是路三。

### 路三：照模板直接编辑 yaml（唯一持久生效的方式）

编辑本目录下的 `products.yaml` / `service.yaml` / `cases.yaml` / `faq.yaml`，按各自注释填写。
没填的字段引擎会剥掉（只剥含"示例："的字符串叶子）；一条里若还有别的值就带着那些值留下，
会以【私有知识库（优先作为事实来源）】的名义每轮注入模型 ——
**不确定的条目整条删掉，比留着写"示例："安全。**

## 填写原则（决定好不好用）

1. **能数字化的绝不写形容词**
   ❌ `响应速度快`　✅ `市区 2 小时内到场`
   模型拿"快"写不出有说服力的句子，拿"2 小时"可以。

2. **参数必须带单位**
   ❌ `载重 1050`　✅ `1050 kg`

3. **每条带来源和日期，但只写真的**
   `source: <资料名，如"2026 版产品手册第 4 章">` / `verified: <你核过的日期>`
   标准参数和型号会换代，没日期的条目迟早变成错误内容。
   ⚠ 这两个字段引擎**不替你判断真假**，但**会**因为空着而降级：条目写了
   `source:` / `verified:` 却留空，注入时会被就地打上 `_未核实`，
   并附一句"只能写成 {{待补：…}} 占位、不许当既成事实播报"（`app/knowledge.py` 的
   `strip_empty`，`tests/test_unverified_facts.py` 钉住）。
   所以**填一个编出来的溯源章比留空更糟** —— 编造的出处会让模型毫无保留地念出去，
   留空至少还会被标出来（本目录曾经就这么干过，假台量因此进了交付脚本）。
   不想被标记的正确做法不是删掉这两个键，而是把真出处写上；
   纯规则/口径类文件（如 `faq.yaml` 的应对话术）本来就没有这两个键，也就不会被连坐。

4. **宁缺毋滥，不确定的留空**
   留空的字段会被剥掉，不注入模型；脚本里缺事实的地方由撰写规则要求模型写
   `{{待补：xxx}}` 占位（导出成品时按占位提示人工补）。
   **填一个错的值，比空着危险十倍。**

5. **只填常用的**
   全部型号塞进来会稀释重点。先填主力机型 3~5 个。

## 填写优先级

| 优先级 | 内容 | 为什么 |
|---|---|---|
| **P0** | 主力型号参数（3~5 个） | 产品推介脚本的硬素材 |
| **P1** | 服务承诺（响应时长、质保、覆盖范围） | 信任建立的核心，比形容词有效 |
| **P2** | 完工案例（5~10 个） | 转化率最高的素材 |
| **P3** | 客户异议应答 | 评论区转化用 |

---

## 不要放什么

| 不放 | 原因 |
|---|---|
| 报价底价、成本价 | 一旦写进知识库，模型可能直接写进脚本 |
| 客户名单、联系人、电话 | 隐私与商业风险 |
| 竞品内部资料 | 法律风险 |
| 未公开的项目信息 | 保密要求 |

**报价的正确处理方式**：不写具体数字，写逻辑和区间规则。
✅ `总价由设备价、安装、土建、管线迁改四部分构成，土建和管线占比常超预期`
❌ `最低 38 万`

|---|---|

| `service.yaml` | 服务承诺、响应时效、覆盖范围 |

## 维护

参数换代、服务政策调整后，更新对应条目并改 `verified` 日期。
建议**每季度过一遍**，过期信息比没有信息更伤专业度。
